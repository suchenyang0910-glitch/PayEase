# Codex + Trae 协作开发规范

> 目标：由一名工程负责人使用 Codex 与 Trae 提升交付效率，同时保持可审计、可复验、不可越过金融与数据安全边界的工程流程。

## 1. 工具分工

| 工作类别      | Codex 主责                         | Trae 主责                    | 人工最终责任     |
| ------------- | ---------------------------------- | ---------------------------- | ---------------- |
| 范围/安全审查 | 解析 PRD、约束、依赖与验收条件     | 展示上下文、协助定位文件     | 产品与安全 Owner |
| 后端/数据库   | 迁移、状态机、契约、测试、代码审查 | 编辑、运行、调试与可视化预览 | 技术负责人       |
| 前端体验      | 组件边界、权限视图、可访问性与测试 | 页面实现、交互调试、视觉微调 | 产品 Owner       |
| CI/CD 与安全  | 门禁规则、依赖审查、失败诊断       | 本地执行与日志辅助           | DevOps / CISO    |
| 发布          | 发布清单、回滚验证、证据整理       | 预览与人工验收辅助           | 双人审批人       |

工具不是授权主体。任何云权限、生产部署、密钥轮换、数据导出、真实 API 连接或合并受保护分支，必须由被授权的人完成并留下审计证据。

## 2. 单人执行节奏

每个任务采用以下闭环，未通过不得进入下一步：

1. **定义**：写明任务 ID、业务域、数据等级、依赖、非目标和验收测试。
2. **设计**：先更新契约/状态机/RBAC/数据字典，再写实现。
3. **实现**：Trae 负责局部编辑与运行预览；Codex 生成/审查代码、迁移和测试。
4. **本地验证**：类型检查、单测、格式、金额守卫、许可证和密钥扫描。
5. **审查**：Codex 做变更范围与安全审查；人工确认涉及产品、合规或资金的决定。
6. **远程验证**：GitHub Actions 通过；生产相关变更额外经过双人审批。
7. **证据归档**：PR、Actions 链接、测试报告、决策记录和演练记录关联任务 ID。

## 4. 强制约束

- 不把真实密钥、令牌、客户资料、日志、截图或数据库导出交给 AI 工具。
- 不接受 AI 生成的安全、合规、利率、授信或资金决策作为最终决定。
- 不允许 AI 直接批准自身代码、绕过 CI、强推 `main` 或执行不可逆生产操作。
- 所有金额均为 `{ amountMinor: string, currency }`；所有跨域契约必须版本化。
- 真实外部集成前，先使用 `fixtures/` 完成成功、拒绝、超时、重放与乱序回调测试。

## 5. 分支与提交规则

- 新功能默认使用 `codex/<task-id>-<short-name>` 分支；紧急修复使用 `hotfix/<id>`。
- 一项可独立回滚的任务一个提交；提交信息采用 `feat|fix|docs|test|ci(scope): summary`。
- 禁止将 `dist/`、`dist-demo/`、`node_modules/`、压缩包、临时目录、真实配置文件或扫描报告默认纳入提交。
- 推送前执行 `git status --short`、`git diff --check`、目标测试；推送后以 GitHub Actions 结果为准。

## 6. 升级与暂停规则

出现以下任一情况，立即停止当前自动化修改并转人工决策：

- S0.2 签字不完整、范围变更涉及真实数据/接口、合规解释存在分歧。
- 发现疑似密钥、PII、账务差异、越权访问、回调重放或非预期资金状态。
- 需要改变产品定价、授信、合同、资金流或数据驻留策略。
