# KhmerX × PayEase V1 薪资贷产品规则

**状态：开发基线（待兰海国际法务、合规与产品负责人最终签署）**
**适用市场：柬埔寨首站**
**产品：PayEase by KhmerX（个人用户端）**

## 1. 品牌、角色与责任边界

```text
KhmerX                 平台主品牌
└─ PayEase             KhmerX 面向个人的薪资贷申请产品

KhmerX Enterprise      企业 HR / 财务核验门户
KhmerX Operations      助贷运营门户
KhmerX Partner         持牌机构及合作方门户
KhmerX Core            多租户、身份、授权、审计、通知、对账、机构连接器
```

| 角色             | 可做事项                                                                 | 禁止事项                                                     |
| ---------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------ |
| 用户             | 提交资料、签服务协议、查看审批结果、签借款合同、查看账单、提交还款凭证   | 查看内部风控、绕过核验、修改已签合同                         |
| 助贷运营         | 资料完整性审核、补件、企业核验催办、异常工单、客服、投诉协同、对账协同   | 授信、定价、决定额度、签发借款合同、放款决定                 |
| 企业 HR / 管理员 | 核验本企业员工身份、在职状态及已授权范围内的薪资信息                     | 查看证件原文、联系人、合同、额度、费用、账单、逾期、风控结论 |
| 持牌机构         | KYC 最终审核、授信、额度、费用、借款合同、放款、账单、催收和最终投诉处理 | 将信贷核心决策委托给助贷或企业                               |

## 2. V1 产品参数

| 参数           | 规则                                                                        |
| -------------- | --------------------------------------------------------------------------- |
| 币种           | USD                                                                         |
| 申请金额       | USD 10–500；存储为最小货币单位字符串 + `currency`                           |
| 借款期限       | 仅 15 天、30 天                                                             |
| 名义年息       | 默认 18.00%，后台版本化配置                                                 |
| 助贷服务费     | 默认 10.50% / 月，后台版本化配置                                            |
| 服务费基数     | 持牌机构获批金额（Gross Approved Principal）                                |
| 服务费支付方   | 用户                                                                        |
| 服务费收取方式 | 从放款金额中扣除；必须在签署前单独显著确认                                  |
| 利息计算       | 单利：`approvedPrincipal × 18% × tenorDays / 365`                           |
| 服务费计算     | `approvedPrincipal × 10.5% × tenorDays / 30`；15 天为 5.25%，30 天为 10.50% |
| 到期日         | 放款成功日期 + 15 / 30 个自然日；节假日顺延规则待机构确认                   |
| 再次申请       | 默认：仅结清后或满足机构定义的拒绝后重申条件；不允许重复进行中申请          |
| 多笔贷款       | 默认不允许。机构可按“优质用户”规则放开未结清总额度上限，不按固定笔数放开    |
| 审批结果有效期 | 7 天；超时未签约自动关闭，需要重新提交申请                                  |

### 2.1 金额与披露

所有金额均使用十进制安全计算及最小货币单位存储，禁止 JavaScript `number` 作为金额 DTO。默认展示时按 USD 分（2 位）四舍五入；实际舍入规则必须由持牌机构确认并写入产品规则版本。

签约确认页必须同时显示：

```text
获批金额（Gross）
利息
助贷服务费
实际到账金额（Net = Gross - 服务费）
到期应还金额（Gross + 利息；如合同另有合法费用，必须逐项展示）
期限、放款日、到期日、还款计划
```

不得只展示“年息 18%”而不展示服务费、实际到账金额和到期应还金额；不得以“低利率、秒到账、保证获批、零门槛”等文案营销。

## 3. 申请、审批、合同与放款流程

```text
Telegram 自动登录
→ KYC 与企业关联
→ 签助贷服务协议、数据处理及企业核验授权
→ 提交申请
→ 助贷资料完整性审核
→ 企业 HR / 管理员核验
→ 持牌机构审批
→ 额度与正式要约（有效 7 天）
→ 用户签持牌机构借款合同
→ 机构签章 / 放款双人审批
→ 放款
→ 账单、还款、人工核销、对账
```

### 3.1 状态机

```text
DRAFT
→ SUBMITTED
→ BROKER_REVIEW
→ EMPLOYER_VERIFICATION
→ LENDER_REVIEW
→ APPROVED_AWAITING_SIGNATURE (有效 7 天)
→ SIGNED_AWAITING_DISBURSEMENT
→ DISBURSING
→ DISBURSED
→ SETTLED

可选分支：
BROKER_SUPPLEMENT_REQUESTED
EMPLOYER_NOT_MATCHED
REJECTED
EXPIRED
OVERDUE
CLOSED
```

状态迁移必须仅追加写入 `application_status_events`，包含操作者、角色、理由代码、理由展示文案版本、请求 ID、前后状态和链式 Hash。

### 3.2 双合同

**合同 A：助贷服务协议（提交申请前签署）**

- 服务范围、服务费规则和收取方式；
- 用户数据处理、向持牌机构传递资料、企业核验授权；
- 未获批、未签约、未放款、撤回时的收费/退款规则；
- 客服与投诉入口；
- 不得写入授信、定价或放款由助贷方决定的表述。

**合同 B：持牌机构个人借款合同（审批后签署）**

- 只能在额度、期限、利息、服务费、实际到账、到期应还和账单计划完整生成后展示；
- 显示持牌机构法定名称、合同编号、投诉渠道及监管表述（以法务批准文本为准）；
- 用户签署后，由机构签章/签署，再进入放款审批；
- 不得在审批前要求用户签署最终借款合同。

合同模板必须版本化：`contractType`、`version`、`language`、生效时间、审批人、内容 Hash、PDF/A 快照和签署证据。已签合同引用的版本和文件永久冻结，后台发布新模板不得回写历史合同。

## 4. KYC、企业核验与资料规则

### 4.1 用户填写资料

必填：

- 姓名；
- 身份证号或护照号（二选一）；
- 居住地址；
- 手机号码；
- 两位联系人：姓名、电话、关系；
- 关联企业/工厂；
- 证件照片。

可选或仅在补件时要求：

- 财富证明；
- 银行流水。

活体认证 V1 先采用人工复核状态流：`未开始 → 已提交 → 人工复核中 → 通过 / 需重试 / 未通过`。接入真实活体、OCR 或外部 KYC 服务前，必须完成供应商 DPA、数据位置和安全评审。

### 4.2 联系人与隐私

- 联系人仅用于身份/紧急联络，不得读取设备或 Telegram 通讯录；
- 用户必须确认已获联系人授权；
- 不得用于营销或不当催收；
- 联系人、证件、活体文件、银行流水暂按长期留存策略管理，但必须加密、最小权限、完整访问审计，并保留法务日后变更删除/匿名化规则的能力。

### 4.3 企业核验

- 一座工厂对应一个独立 `employerTenantId`；
- 用户自行选择企业/工厂；
- 匹配主键是加密证件号的独立 HMAC 查询值；HR 不可见证件原文或 HMAC；
- HR 只返回 `MATCHED` / `NOT_MATCHED` 及被授权的在职/薪资区间核验结果；
- 提交时立即通知企业 HR；12 小时首次提醒、24 小时升级企业管理员、48 小时创建助贷异常工单并通知用户核验处理中；提醒应遵循企业工作时段。

## 5. 放款、账单与人工核销

### 5.1 收款账户

用户填写：银行名称、银行卡/账户号码、持卡人姓名，并勾选确认。账户号加密保存、列表脱敏。变更账户后必须重新确认并进入人工复核。

### 5.2 放款与核销

```text
放款经办创建放款指令
→ 放款复核人批准
→ 人工放款
→ 记录放款成功时间、凭证和账单

用户按官方指引还款
→ 可提交付款凭证
→ 核销经办检查
→ 核销复核批准
→ 已核销 / 需补充凭证
```

付款凭证上传不等于还款成功。所有人工放款、调整、核销都需要经办/复核分离、理由和不可修改审计记录。

## 6. 用户端功能

| 页面/入口           | 能力                                                                                            |
| ------------------- | ----------------------------------------------------------------------------------------------- |
| 首页                | KhmerX 主品牌 + `PayEase · by KhmerX`；额度入口、快捷入口、合规提示；保持干净，不混入旧申请表单 |
| 立即申请 / 我要借款 | 新建或继续草稿；存在进行中申请时打开申请/订单，不重复创建                                       |
| 借款                | 申请表单、资料补件、申请进度、借款记录、合同与获批结果                                          |
| 账单 / 还款管理     | 待还、已还/未还期数、下一还款日、付款指引、凭证、核销状态                                       |
| 额度提升            | V1 仅显示申请资格或提交申请；不承诺自动提额                                                     |
| 我的                | Telegram 已验签资料、手机验证、企业、KYC 状态、语言、授权版本、客服与投诉                       |

语言为高棉语、英语、中文。用户选择的语言通过已认证会话保存并在下次登录恢复；不得将 token、Telegram `initData`、手机号、证件或合同保存在 `localStorage` / `sessionStorage`。

## 7. 用户可见拒绝/异常文案

仅展示可行动的理由，不展示内部风控策略：

- 资料不完整，请补充所需文件；
- 企业信息暂未匹配，请核对所选企业或联系 HR；
- 当前暂不符合申请条件；
- 审批结果已过期，请重新提交申请；
- 收款账户信息需人工复核。

客服与投诉统一使用现有 `KhmerXBot`，不得在 Bot 或客服对话中索取密码、OTP、完整银行卡号或完整证件号。

## 8. 发布前必须确认

以下内容必须由兰海国际及当地法务签署后发布真实产品：

1. 18% 年息与 10.5%/月服务费的适用范围、总成本披露和监管合规意见；
2. 服务费在未获批、未签约、撤回、放款失败时的处理；
3. 节假日顺延、提前结清、逾期、投诉和催收规则；
4. 双合同最终模板、高棉/英语/中文效力顺位和电子签约二次认证方式；
5. 数据长期留存的期限、访问范围、跨境位置和最终删除/匿名化例外；
6. 活体、OCR、KYC 供应商与银行/支付通道的正式接入授权。
