# KhmerX 官网内容、SEO 与 GEO 规划

**目标受众：** 柬埔寨个人用户、工厂 / 企业、持牌金融机构、投资人与合作方。
**品牌口径：** KhmerX 是数字商业与金融协作平台；PayEase 是面向个人的产品；最终授信、借款合同、放款、催收与最终投诉由接入的持牌金融机构独立承担。
**语言：** 高棉语 `km`、英语 `en`、中文 `zh-CN`。
**重要原则：** SEO / GEO 的目标是让真实、可验证、结构清晰的信息更容易被用户和搜索 / AI 系统理解，不能用虚构案例、夸大承诺、伪造政府或牌照背书换取流量。

## 1. 官网定位与转化路径

官网不是 PayEase Mini App 的复制品，而是 KhmerX 的信任与合作入口：

```text
了解 KhmerX
├─ 个人用户：理解 PayEase → 从 Telegram 开始申请
├─ 企业：了解员工核验协作 → 提交合作咨询
├─ 金融机构：了解 Partner 能力 → 申请合作洽谈
└─ 投资人 / 媒体：理解平台、治理与路线图 → 获取资料
```

主导航建议：

```text
KhmerX Logo | 平台 | PayEase | 企业合作 | 机构合作 | 安全与合规 | 资源中心 | 关于我们 | 语言
```

主 CTA 按受众分流：

- `打开 PayEase`：只在 Telegram / 已授权设备展示深链；Web 端展示“在 Telegram 中打开”的步骤。
- `企业合作咨询`：合规表单，最少收集姓名、企业、工作邮箱 / 联系方式、需求类别。
- `机构合作咨询`：机构名称、司法辖区、牌照 / 业务范围、联系人、合作方向；不在表单要求 API 密钥或客户数据。

## 3. 首页内容结构

1. **首屏**：`KhmerX - Digital commerce and financial collaboration for Cambodia`；说明 PayEase 是个人产品、企业和持牌机构是协作方。
2. **三类入口**：`For Individuals`、`For Enterprises`、`For Financial Partners`，每个入口只讲一类用户的价值。
3. **协作方式**：个人提交资料 → 企业经授权核验 → 持牌机构独立审核 → 用户查看合同、账单与还款支持。
4. **产品生态**：当前突出 PayEase；Enterprise / Partner 说明为协作门户；未来产品以“路线图”标识。
5. **安全与透明**：最小数据、透明披露、审计、合作机构独立决策。
6. **资源与 FAQ**：高棉语优先的 3 - 5 个关键问答。
7. **页脚**：主体信息、语言、隐私、条款、投诉、无障碍、社媒（如存在）。

## 4. PayEase 产品页内容结构

### 应回答的事实问题

- PayEase 是什么？它是 KhmerX 面向个人的数字产品。
- 谁决定额度与合同？接入的持牌金融机构独立审核并在确认前展示条款。
- 用户会经历哪些步骤？Telegram 登录、资料与企业选择、服务协议 / 授权、企业核验、审核、报价、借款合同、账单与还款支持。
- 当前可选的期限和金额？V1 为 USD 10 - 500，15 或 30 天；最终资格与金额由审核决定。
- 用户何时看到费用？在确认前以批准金额、服务费、利息、实际到账、到期应还和合同版本完整展示。
- 用户如何投诉？通过指定 KhmerXBot / 正式渠道提交；合同、放款、催收类最终投诉由持牌机构处理。

### 禁止的 SEO 营销词

不写、也不在 meta title / description / FAQ / 图片 alt 中变体使用：

```text
guaranteed loan, instant approval, no documents, lowest interest,
zero-risk loan, 秒到账, 保证下款, 无条件, 零门槛, 最低利率
```

## 5. 三语 SEO 内容模型

### 5.1 URL 与 hreflang

建议三语言都具备独立可索引 URL：

```text
/km/                 高棉语（默认面向本地用户）
/en/                 英语
/zh-cn/              中文
```

每一页：

- 使用自身 canonical URL；不要把三种语言全部 canonical 到英语页。
- 输出互相对应的 `hreflang="km"`、`hreflang="en"`、`hreflang="zh-CN"` 与 `x-default`。
- `<html lang>` 和页面正文语言一致；不能用机器翻译页面替代人工审核的高棉语金融内容。
- 翻译不是逐字替换：同一事实、同一责任边界、同一版本日期，但按照语言与本地表达重写。

### 5.2 Title / Description 模板

| 页面    | English Title      | 中文 Title                                                | 高棉语策略                                |
| ------- | ------------------ | --------------------------------------------------------- | ----------------------------------------- |
| 首页    | `KhmerX            | Digital Commerce and Financial Collaboration in Cambodia` | `KhmerX｜柬埔寨数字商业与金融协作平台`    | 高棉语主标题由母语审核，包含 KhmerX 与“数字协作”语义 |
| PayEase | `PayEase by KhmerX | Salary Loan Application Support`                          | `PayEase by KhmerX｜薪资贷申请与流程支持` | 避免“低利率 / 快速获批”词汇                          |
| 企业页  | `KhmerX Enterprise | Employee Verification Collaboration`                      | `KhmerX Enterprise｜员工核验协作`         | 明确企业不做授信                                     |
| 机构页  | `KhmerX Partner    | Licensed Financial Institution Collaboration`             | `KhmerX Partner｜持牌金融机构协作`        | 不暗示任何机构已合作，除非公开授权                   |

Description 长度按搜索结果可读性控制，不承诺固定字符数；必须包含一项明确事实、目标受众、下一步，不堆叠关键词。

## 6. GEO（生成式搜索优化）内容原则

GEO 的核心是让 AI 搜索、问答系统与用户可以**准确引用**页面，而不是为模型写虚假“提示词”。每个关键页应具备：

1. 首段用 40 - 70 字直接定义页面主题和服务范围。
2. 使用问题式 H2 / H3，例如“PayEase 如何处理薪资贷申请？”、“企业在流程中核验什么？”。
3. 每个回答先给简短结论，再给流程、边界和链接；避免只用营销口号。
4. 事实性声明标明版本 / 最后更新日期、适用市场和责任主体。
5. 价格、费率、产品可得性等动态内容以“以审核和确认页为准”表述，并连接到版本化费用说明页。
6. 为文章标注作者 / 审核者角色，例如 `KhmerX Product Team`、`Compliance Review`，不得虚构专家、机构或认证。
7. 维护 FAQ，答案简短、去重、与正文事实完全一致；复杂法规问题应说明“需以当地法务 / 持牌机构确认”。
8. 发布真实可验证的流程图、术语表、隐私 / 安全说明和更新时间；这些比大量泛内容更有引用价值。

**不建议**：伪造问答、隐藏文本、关键词堆砌、声称“被某 AI 推荐”、批量低质量 AI 文章、虚构客户案例或合作方。

## 7. 结构化数据与机器可读性

| 页面     | JSON-LD 建议              | 注意事项                                           |
| -------- | ------------------------- | -------------------------------------------------- |
| 全站     | `Organization`, `WebSite` | 主体名称、Logo、官网、联系信息必须真实且跨页面一致 |
| 产品页   | `Product` 或 `Service`    | 不标记虚构评分、价格、库存、贷款保证               |
| FAQ      | `FAQPage`                 | 仅标记页面上真实可见且非重复的问答                 |
| 指南文章 | `Article` / `BlogPosting` | 作者、发布日期、更新日必须真实                     |
| 联系页   | `ContactPage`             | 仅使用经过确认的客服 / 合作联系方式                |
| 面包屑   | `BreadcrumbList`          | URL 与导航结构一致                                 |

技术补充：

- SSR / SSG 输出真实正文、title、description、canonical 与 JSON-LD；不要让关键页面只能依赖客户端 JS 才出现内容。
- 自动生成 `/sitemap.xml`，按语言与最后更新时间列出可索引页；`robots.txt` 引用 sitemap。
- 禁止索引：登录、用户订单、KYC、合同、后台、预览、错误页、带个人参数的 URL。
- `llms.txt` 可作为补充的简明站点说明，但不是 SEO 或 GEO 的替代品；其中只列真实公开页面和事实。
- 性能目标：移动优先、压缩图片、稳定布局、避免阻塞脚本；Core Web Vitals 通过真实监测评估。

## 10. SEO / GEO 上线验收清单

- [ ] 每个公开页面有唯一 title、description、H1、canonical、语言标记和可读正文。
- [ ] 三语页面有正确 hreflang 与同事实内容；高棉语金融文案完成母语审核。
- [ ] 公开页面的主体、责任边界、产品范围、费用披露与合同 / 产品规则一致。
- [ ] Schema 通过结构化数据验证；不含虚构评分、评论、价格或认证。
- [ ] `/sitemap.xml`、`robots.txt`、404、重定向、noindex 私密页均验证。
- [ ] 登录 / KYC / 合同 / 后台 URL 不被索引，也不出现在站点地图。
- [ ] 图片有描述性 alt，Logo 与页面图片被压缩且不含 PII。
- [ ] FAQ 与页面正文一致、可被直接引用、含最后更新时间。
- [ ] 使用 Search Console / Web Analytics / 性能监测后，按真实查询、跳出和转化数据迭代；不以虚假流量作为 KPI。
