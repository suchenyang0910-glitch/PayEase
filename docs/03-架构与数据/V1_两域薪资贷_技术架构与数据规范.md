# V1 两域薪资贷技术架构与数据规范

**版本**：V1.0｜**状态**：开发基线｜**关联总则**：[规范基线](../00-导航与治理/V1_两域薪资贷_规范基线.md)

## 1. 物理隔离

| 域            | 独立资源                                                        | 权威数据                                                     |
| ------------- | --------------------------------------------------------------- | ------------------------------------------------------------ |
| KhmerX 助贷域 | 仓库/VPS/VPC、`broker_db`、对象存储、KMS、Redis、Cookie、管理员 | 申请资料、企业核验、服务协议、居间服务费、企业协作和用户投影 |
| 持牌机构域    | 仓库/VPS/VPC、`lender_db`、对象存储、KMS、Redis、Cookie、管理员 | 授信、报价、借款合同、放款、本息账、核销、征信与最终投诉     |

禁止共享数据库、存储桶、KMS、会话、管理员账户或内部主键。跨域仅传 `externalApplicationRef` 等外部引用和最小化加密包。

## 2. 核心数据模型

所有权威事实表追加写入；当前状态表仅为投影。每一事件至少含 `eventId`、`sourceDomain`、`occurredAt`、`actorRef`、`requestId`、`idempotencyKey`、`previousState`、`nextState`、`reasonCode`、`workflowVersion` 和链式 Hash。

### 2.1 KhmerX 助贷域

- `employer_tenants`、`employer_payroll_rule_versions`：工厂、发薪节点、允许回收方式、法务启用状态。
- `employee_roster_versions`：受控导入；证件原文加密，匹配 HMAC 单独存储且不可展示。
- `applications`、`application_status_events`、`broker_application_projections`。
- `repayment_method_snapshots`、`employer_deduction_execution_events`：仅存该域授权/执行事实与持牌域所需投影。
- `brokerage_remuneration_rule_versions`、`brokerage_remuneration_receivables`、`brokerage_payment_proofs`、`brokerage_payment_acceptances`。
- `employer_revenue_share_rule_versions`、`employer_revenue_share_statements`、`employer_revenue_share_events`。

### 2.2 持牌机构域

- `lender_cases`、`lender_case_events`、`lender_decisions`、`lender_quotes`。
- `lender_contract_evidence_receipts`、`lender_contract_evidence_acceptances`。
- `lender_disbursement_events`、`lender_repayment_plan_snapshots`、`lender_collection_events`、`lender_payment_acceptances`。
- `credit_inquiry_consents`、`credit_inquiry_audit_events`、加密征信证据存储；不跨域同步原始报告。

## 3. 安全与隐私

- 身份证/护照、账户号、证件/视频/签名、联系人、银行流水均使用信封加密；密钥按域分离。
- 列表、日志、事件、通知、导出不得出现证件原文、HMAC、完整账户号、视频 URL 或原始征信数据。
- 用户会话为服务端验证 Telegram `initData` 后签发的 HttpOnly、Secure、SameSite Cookie；不得存 token/initData/敏感资料到浏览器存储。
- 每工厂强制租户过滤与行级策略；HR/财务默认拒绝访问非授权字段。
- 所有放款、费用复核、核销、分润结算均需 maker-checker；同一账号不得经办和复核同一事项。

## 4. 状态与一致性

任何跨域事件只能驱动接收方本地投影，不存在共同写入的 `application.status`。接收方校验签名、时钟窗口、事件版本和幂等键；重复事件返回同一结果，乱序事件进入待处理队列/异常工单，禁止静默覆盖。

## 5. 计算与规则版本

规则引擎必须接受不可变快照：`productRuleVersion`、`feeRuleVersion`、`payrollRuleVersion`、`repaymentMethodSnapshot`、`repaymentPlanSnapshot`、`contractVersion`。服务器是唯一金额和日期计算权威；前端仅展示预估。历史订单不得因工厂发薪节点、费率或分润规则更新而重算。
