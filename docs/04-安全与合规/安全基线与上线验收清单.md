# 安全基线与上线验收清单

> 验收基线：OWASP ASVS 5 + OWASP API Security Top 10
> 红线原则：任一 P0 项未通过，不得接入真实用户/真实持牌机构。

## 1. 平台安全基线（P0 全量）

### 1.3 身份与会话安全

| #       | 控制项                       | 验收标准                                                                                                                                                                                                                                                                                                                              | 验证方法                                                                                                                                          |
| ------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| AUTH-01 | Telegram initData 服务端验签 | 后端使用 Bot Token HMAC-SHA256 校验；拒绝无效签名                                                                                                                                                                                                                                                                                     | 篡改签名测试                                                                                                                                      |
| AUTH-02 | auth_date 时效校验           | initData 签发时间距当前 > 5min 直接拒绝                                                                                                                                                                                                                                                                                               | 过期 initData 测试                                                                                                                                |
| AUTH-03 | 登录幂等 + 会话防重放        | 登录交换接口对**同一有效 initData 在短窗口（60s）内幂等返回同一会话或安全失败结果**，不得借此创建多会话；新 Session 创建前必须校验「同 initData 未创建过有效 Session」（Redis `session:initdata:{hash}` 键 TTL = Session TTL）。合法网络重试不得导致用户无法登录；会话到期后只能用新的、仍在 `auth_date` 时效内的 initData 创建会话。 | ① 同 initData 短时间二次请求应返回同一 Session ② 过期 initData 新建 Session 拒绝 ③ 会话到期后复用同 initData 拒绝；新的有效 initData 可新建且审计 |
| AUTH-04 | 会话有效期与轮换             | 用户端 Session ≤ 2h；关键操作强制重新验签；Session 绑定 IP/UA 指纹，漂移时二次校验                                                                                                                                                                                                                                                    | 超时 + 指纹漂移测试                                                                                                                               |
| AUTH-05 | 管理端 OIDC + MFA            | 运营/机构/企业后台 OIDC + TOTP/WebAuthn MFA；首次登录强制绑定                                                                                                                                                                                                                                                                         | 无 MFA 登录尝试测试                                                                                                                               |
| AUTH-06 | 管理端短会话与风险控制       | 管理端 Session ≤ 30min；异地/异常 IP 触发二次验证或锁定                                                                                                                                                                                                                                                                               | 异常 IP 登录测试                                                                                                                                  |
| AUTH-07 | 设备/IP 审计                 | 所有登录事件记录 User-Agent、IP、位置（合规允许范围内）并进入审计日志                                                                                                                                                                                                                                                                 | 审计日志检查                                                                                                                                      |

| ENC-04 | 脱敏展示                            | 列表/通知/日志/工单中证件号、银行卡号仅显示脱敏值（如 ****1234）                                                                                                                                                                                                | 各页面/接口响应检查                                  |
| ENC-05 | 敏感值日志禁令                      | 日志、埋点、异常栈、通知、客服工单正文禁止出现原始身份证号、银行卡号、完整薪资；日志 pipeline 内置正则脱敏拦截器                                                                                                                                                | 代码 + 日志样本扫描                                  |
| ENC-06 | 金额整数存储与 API 传输             | 所有金额数据库使用 `BIGINT` 最小货币单位（分/厘）；代码中用 `{ amountMinor: string; currency: Currency }` 类型，**禁止 `number` 表示金额**；API JSON 中金额使用字符串传输（规避 JS 安全整数上限）；运算强制 big.js/bigint；代码库无 float/double 金额计算路径。 | 类型定义审计 + 代码扫描 + 数据库列类型审计           |
| ENC-07 | 短时文件 URL + 可选一次性令牌       | S3 预签名 URL **有效期 ≤ 5 分钟**，仅限指定对象键与 `GetObject` 方法；V1 承认「有效期内可重复使用」。如业务需要强制一次性下载，须额外部署下载令牌服务：先 `claim`（记录消费状态）→ 再签发短 URL，二次 claim 返回拒绝。                                          | 过期 URL 访问 + 一次性令牌二次消费测试               |

| WEB-07 | Referrer 与其他安全头                        | `Referrer-Policy: strict-origin-when-cross-origin`；`X-Content-Type-Options: nosniff`；`X-Download-Options: noopen`；`X-XSS-Protection: 1; mode=block`（兼容旧浏览器）；`Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=()`（按需放开）                          | HTTP Header 扫描                                                                            |
| WEB-08 | 依赖与构建安全                               | 前端构建产物 integrity hash；子资源完整性 SRI 引入第三方 CDN；`npm install --ignore-scripts` 高危包安装后审计 postinstall                                                                                                                                                               | npm ls --prod 依赖审计 + SRI 缺失扫描                                                       |

## 2. API 与业务安全（P0 全量）

### 2.1 跨域 API 契约

### 6.3 删除流程（P0，§4 上线红线 09 细化）

```
用户/监管删除请求
  → 合规受理（判断是否处于法定留存/争议期）
    → 是 → Legal Hold 标记 + 告知原因
    → 否 → 数据分类 + 范围确认
      → 数据库软删（写入 deleted_at + 审计事件 DATA_DELETION_INIT）
      → S3 对象版本 + 删除标记（含元数据 Tombstone）
      → 备份/PITR 中数据：通过新的 PITR 演练 + 到保留期后自然过期覆盖
      → 生成删除证明：受影响实体列表 + 哈希 + 执行时间 + 操作者签名
        → 写入 `data_deletion_proofs` 表（追加写，不可篡改）
      → 通知请求方（若要求）
```

### 7.2 轮换要求自动化（P0）

- KMS CMK：启用 AWS KMS 自动密钥轮换（每年一次，无需应用变更）
- Secrets Manager 托管的 DB/API 密钥：配置 Rotation Lambda（30/60/90 天按资产类型），应用端缓存 15min 自动刷新
- mTLS 证书：ACM PCA 证书 90 天有效期 + ACM 自动续签 + ECS Sidecar 热加载（无需重启）
- HMAC 签名密钥：支持 `X-Signature-Key-Id` 双密钥并行 24h 切换窗口；轮换窗口期内新旧密钥均可验签

### 7.3 密钥泄露紧急替换流程（P0，上线红线 10）

```
告警或发现密钥泄露
  → T0（15min）：安全负责人 + 资产所有者召开桥接
  → T1（30min）：立即吊销/禁用旧密钥
        - KMS：Disable Key → 计划 Schedule Key Deletion（7 天等待窗口）
        - Bot Token：/revoke 生成新 Token
        - 签名密钥：加旧 Key Id 黑名单 → 仅接受新 Key Id
        - DB：Rotate Password → 中止可疑连接
  → T2（1h）：注入新密钥 → 冒烟测试服务可用
  → T3（4h）：分析泄露窗口日志 → 列出受影响数据范围 → 判断是否需要数据重新加密
        - 若 DEK 绑定泄露 CMK → 启动批量重新加密 Job（新 CMK wrap 新 DEK）
  → T4（24h）：生成事件报告（泄露原因、影响、补救、改进项）→ 存档 + 通知合规
  → T+7 日：恢复演练复盘，永久删除旧密钥材料（KMS Deletion 窗口结束确认）
  → 每季度：至少 1 次「模拟泄露 → 替换全流程」演练，记录并优化 RTO
```

### 8.2 事件响应流程（P0，IR 计划）

```
P1/P2 安全事件告警
  → 15min 内安全值班确认 + 拉桥接（安全/业务/运维/法务）
    → Triage：误报 ← 关闭 + 调规则；真实事件 → Severity 定级
      → 遏制（Containment，1h）：封禁 IP/账号、禁用密钥、只读模式、中断可疑连接
      → 根除（Eradication，4-24h）：移除后门、轮换密钥、打补丁、清除持久化
      → 恢复（Recovery，按 RTO）：服务恢复 + 冒烟 + 扩大监控
      → 报告（Post-Mortem，5 工作日）：5 Whys + 修复 Backlog + 改进计划
        → 按监管要求上报合规机构 / 用户通知（按法律评估）
→ 每次事件复盘更新告警规则 + Runbook
→ 每季度至少 1 次桌面演练（Tabletop）：
  ① 数据泄露 ② Bot Token 泄露 ③ Ransomware 加密桶 ④ 合作方回调伪造 ⑤ 管理员账号劫持
```

每条数据流交付物：DFD 图（Mermaid/PlantUML）+ STRIDE 威胁识别表（≥ 每类 1 条实际威胁）+ 对应缓解措施编号（关联本文档基线编号）+ 未缓解威胁的风险接受签字（仅可接受 P3 Low，不得接受 P0/P1）。

### 10.3 架构安全评审门禁

- 每次大版本（S0-S6 结束）+ 每次新增外部 API/数据流 → 触发架构安全评审；
- 评审必须包含：安全负责人、架构师、对应业务模块 Owner、可选外部审计师；
- 评审结论通过才能进入下一迭代或接入真实环境；
- 评审记录 + 威胁模型文档进入 `partner-contracts/security/` 版本化管理。
