## 1. 解除的限制

Trae 可以开始实现以下代码，不再因“仅演示 / 仅文档”冻结：

- 用户端申请、KYC、Telegram 已验签 Profile 展示、订单、账单、人工付款凭证、语言偏好；
- 助贷运营端的资料完整性审核、补件、企业核验催办、客服 / 投诉、异常工单、对账协同；
- 企业 HR 核验端的本租户在职 / 薪资核验待办；
- 合作金融机构端的组织、部门、角色、账号、KYC / 额度 / 报价 / 合同 / 放款 / 核销审批；
- 版本化产品规则、服务协议 / 借款合同、审批状态机、RBAC、审计事件、通知与任务队列；
- 本地 / 测试数据库迁移、fixture、集成测试、E2E 受控测试。

## 2. 未解除的安全边界

“开始正式业务代码”不等于允许跳过生产控制。以下仍必须保持：

- 所有真实银行、支付、HRIS、KYC/活体、电子签、机构 SDK 均通过**连接器接口 + 环境配置开关**接入；不得在页面或业务逻辑硬编码真实密钥、账号、URL。
- 生产放款、核销和合同签署必须走审批流、角色权限、审计和幂等键；前端不能直接将订单改成 `DISBURSED`、`SETTLED` 或 `SIGNED`。
- Telegram 只接受服务端验签的 `initData`；多 Bot、HttpOnly Cookie、防重放、手机号 webhook 校验不得回退。
- 金额仍使用最小单位字符串 + 币种；禁止 JS `number` 金额 DTO。
- 一座工厂一个 `employerTenantId`；跨租户 / 跨角色默认拒绝。
- 证件、手机号、联系人、收款账户加密存储；列表、日志、通知、审计全部脱敏。

## 3. 实施顺序（不可跳步）

```text
F1 共享领域模型、迁移、状态机、审批与审计基础
F2 用户端：登录资料、申请/KYC、服务协议、审核进度
F3 企业端：租户、HR 核验、提醒与异常
F4 助贷运营端：资料、补件、催办、客服/投诉、对账工单
F5 机构端：组织/RBAC、审核、报价、借款合同、审批流
F6 人工放款、账单、人工核销、对账、通知
F7 四端 E2E、权限/安全/失败恢复测试、发布验收
```

每个阶段完成时，Trae 必须先提交：变更清单、迁移影响、权限矩阵、测试输出和 `git diff --stat`；由 Codex 复核后再进入下一阶段。**Trae 不执行 git commit、push、部署、生产数据迁移或真实资金操作。**

## 4. V1 默认组织与审批分离

- 平台管理员可维护：`部门 → 角色 → 账号 → 数据范围`，所有变更审计。
- 助贷运营人员可做资料 / 补件 / 催办，不可做授信、定价、合同终签、放款或核销终审。
- 企业 HR 仅核验本企业员工资料，不参与信用审批。
- 合作金融机构负责审批、报价、借款合同、放款、催收、最终投诉；经办与复核必须分离。
- 初始 USD 10–500 可采用同一审批层级；审批策略必须版本化，后续能配置 USD 200 以上增加复审而无需重写状态机。
