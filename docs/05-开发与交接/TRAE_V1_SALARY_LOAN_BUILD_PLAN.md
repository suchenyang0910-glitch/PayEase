# Trae 编码任务：KhmerX × PayEase V1 薪资贷闭环

**依据：** `docs/01-产品与业务/V1_SALARY_LOAN_PRODUCT_RULES.md`
**目标：** 交付可用于受控试点的 V1 闭环：申请 → 资料审核 → 企业核验 → 机构审批 → 双合同 → 人工放款 → 账单 → 人工核销 → 对账与客服协同。
**非目标：** 自营资金池、平台授信、自动放款、真实银行/HRIS/KYC SDK 接入（除非单独获得书面授权）。

## 0. 执行纪律

1. 先读产品规则文档和现有 `TRAE_CODING_HANDOFF.md`，不要凭旧 UI 结构推断业务规则。
2. 每个任务只改本任务需要的文件；禁止全仓格式化、`git add -A`、提交构建产物、真实 PII、Token 或合同样本。
3. 不得删除多 Bot 验签、租户隔离、加密/HMAC 匹配、金额字符串守卫、审计 append-only 限制。
4. 代码完成后必须运行任务对应测试；全部完成后才运行全量门禁。
5. 不执行 `git commit`、`git push`、部署或真实第三方调用；交由 Codex 审查、远程 CI 和发布。

## 1. P0-1：产品规则与金额试算

### 交付

- 在 `partner-contracts` 增加版本化产品规则 schema；
- 在 `packages/v1-domain` 或既有受控业务域增加纯函数试算；
- 金额输入/输出保持 `{ amountMinor: string; currency: "USD" }`；
- 支持期限只允许 `[15, 30]`；
- 默认规则：年息 1800 bps、服务费月费率 1050 bps；
- 服务费随期限按 `tenorDays / 30` 比例计算；
- 返回 gross、interest、serviceFee、netDisbursement、repaymentDue、dueDate 的结构化结果；
- 费率/计算基数/舍入规则/合同模板版本必须由 `productRuleVersion` 固定引用。

### 验收

- USD 100 / 15 天：服务费 `$5.25`；
- USD 100 / 30 天：服务费 `$10.50`；
- 不接受 7、14、31、90、180 天；
- 不接受 `number` 金额 DTO；
- 费率改版不改变已有报价快照。

## 2. P0-2：申请与 KYC 表单

### 交付

- 用户端将“首页”保持为纯导航/品牌页；申请流程放在“借款”Tab；
- 新建/继续草稿/进行中申请拦截；
- 资料分步：身份、住址、手机号、两位联系人、企业选择、证件、可选补件、人工活体状态；
- 联系人必须手动录入并显式确认授权；绝不读取通讯录；
- 文件上传状态只展示类型与审核状态，原文件不进浏览器日志；
- 用户选择工厂后，`employerTenantId` 必填；
- 服务协议和数据/企业核验授权未确认时禁止提交。

### 验收

- 缺少任意必填字段、企业、两位联系人或协议确认时无法提交；
- 证件号、手机号、联系人号码不出现在列表、日志、toast 或 URL；
- 同一用户提交中申请不会重复创建；
- 中文/英语/高棉语切换后草稿与已保存语言行为符合现有会话边界。

## 3. P0-3：助贷审核与企业核验

### 交付

- 助贷端队列只支持资料完整性、补件、催办和异常工单；
- 企业端仅显示本租户核验任务，返回 `MATCHED` / `NOT_MATCHED` 与已授权字段；
- 企业核验提醒任务：提交立即通知、12h、24h、48h 升级；
- 48h 创建异常工单并向用户展示中性状态文案；
- 每次状态迁移记录 append-only 审计事件。

### 验收

- HR 无法读取其他企业数据、额度、费用、合同、账单、联系人或证件；
- 助贷人员不能把申请改为 APPROVED / DISBURSED；
- 跨租户访问返回 403；
- 提醒任务幂等，不因重试重复创建同一升级工单。

## 4. P0-4：持牌机构审批、额度与多笔规则

### 交付

- 机构端审批：通过、拒绝、补件、报价、关闭；
- 报价包含获批金额、15/30 天、利息、服务费、实际到账、应还金额、到期日、规则版本；
- 默认拦截任何未结清贷款的新申请；
- 增加受控 `preferredBorrower` 资格和 `outstandingPrincipalCap` 总额上限，机构角色配置且完整审计；
- 报价有效期 7 天，到期自动转 `EXPIRED`。

### 验收

- 只有持牌机构权限可创建/批准报价；
- 超出未结清总额度上限被拦截；
- 过期报价不能签合同或放款；
- 用户端只见审批结果和行动提示，不见内部风控标签/规则。

## 5. P0-5：双合同与签约证据

### 交付

- 合同 A：`BROKER_SERVICE`，提交前签；
- 合同 B：`LENDER_LOAN`，审批后、完整报价生成后签；
- 合同内容后台以“草稿 → 法务/业务审批 → 发布版本”管理；
- 每笔合同生成 PDF 快照、版本、Hash、语言、确认事件、签署时间、用户会话证据；
- 签约前展示 gross、服务费、net、应还金额、期限、到期日和还款计划；
- 二次认证方式做成策略接口，V1 先使用经法务确认的 Telegram/OTP 方案，禁止伪造签约成功。

### 验收

- 审批前不能签 `LENDER_LOAN`；
- 未签服务协议不能提交申请；
- 修改模板后，历史合同 PDF/Hash 不变；
- 所有签约/撤销/重新签约事件可审计且不可更新删除。

## 6. P0-6：人工放款、账单、核销与对账

### 交付

- 收款账户：银行、账户号、持卡人；加密存储、列表脱敏、修改重审；
- 放款：经办创建 → 复核批准 → 标记成功/失败；
- 放款成功才生成账单与到期日；
- 账单显示已还/未还期数、下一期金额/日期、待核销和逾期状态；
- 用户付款凭证 → 核销经办 → 核销复核；
- 对账差异生成工单，禁止直接修改账本抵消。

### 验收

- 同一放款回调/人工动作幂等；
- 经办不能复核自己创建的放款或核销；
- 付款凭证上传不自动变成已还；
- 已结清后状态不可回退为已放款。

## 7. P1：客服、投诉、通知与数据权利

### 交付

- 用户端客服/投诉跳转或深链至 `KhmerXBot`；
- 分类：通用咨询、申请、还款、投诉、安全事件；
- 合同、放款、催收、最终投诉决定自动转持牌机构队列；
- 多语言通知模板与发送审计；
- 长期留存数据的访问审计、导出控制、未来删除/匿名化策略接口。

### 验收

- Bot 与客服不索取密码、OTP、完整卡号、完整证件号；
- 机构升级过程可追溯；
- 通知失败可重试但不重复发送。

pnpm test

pnpm --filter @payease/broker-api run test:integration  # 配置测试 PostgreSQL 后

还必须检查：

- Semgrep、金额守卫、许可证守卫、Gitleaks；
- 租户隔离 403；
- 角色越权 403；
- 状态机非法迁移拒绝；
- 费用试算与合同展示一致；
- 双人复核分离；
- 合同/审计不可篡改；
- 多 Bot 验签与旧 initData 防重放。
