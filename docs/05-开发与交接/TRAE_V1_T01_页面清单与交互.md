# Trae V1 T01：PayEase Mini App 页面清单与交互

**任务类型**：前端页面与受控交互。**依赖**：规范基线、T02 字段字典、T03 状态机。**禁止**：真实银行/支付/活体 SDK、真实 PII、直接读写持牌库。

## 目标

在现有 Mini App 基础上完成可演示、可测试的 V1 用户路径。所有服务端结果使用 mock/受控 API 契约；禁止以前端状态伪造“已放款”“已还款”。

## 首次与再次进入

```text
Telegram Mini App 打开
  ├─ 有效受控会话 + 语言偏好 → 首页
  ├─ 有效受控会话 + 无语言偏好 → 欢迎页 → 首页
  └─ 验签/会话失败 → 恢复页 → 从 Bot 重新打开
```

## 关键交互规则

1. KYC 提交后产生“最低 USD 50 的系统建议值”，仅后台批准后才展示正式额度。
2. 24 小时为服务目标文案，显示“预计 24 小时内返回，请以通知为准”，不得作为保证。
3. 签名画布提交生成证据引用；用户可重新签名，旧草稿不作为最终签署证据。
4. 提现与还款操作的唯一前端入口是 KhmerX 创建的一次性 `wallet operation jump`；Mini App 不得直连持牌机构资金 API。
5. 用户点击提现或还款后，打开 SMILE 受控钱包页；支付密码、银行卡令牌、银行授权、OTP 仅在 SMILE 域输入和处理。
6. 提现必须先冻结金额，再进入持牌机构钱包/支付域处理；成功回调后完成扣减，失败/取消/超时按状态机处理。
7. 还款跳转银行前显示金额、收款主体、订单号；从银行返回仅显示“处理中”，以服务端验签回调为准。
8. V1 不存在“工资代扣 / 用户本人账户代扣 / 用户主动付款”三种回收方式选择；统一为用户主动发起银行或支付机构授权还款。

## T01 验收

- km/en/zh 文案切换并恢复；小屏 320px 不溢出。
- 首次、再次、失效会话三条路径都有组件测试。
- 金额 DTO 只接受 `amountMinor: string`；密码、令牌、OTP 不写入 localStorage/sessionStorage/日志。
- 所有 P01–P15 有 loading、empty、error、disabled 四类状态。
