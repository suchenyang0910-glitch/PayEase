# Trae V1 T05：后台审批流、权限与人工处理

**任务类型**：Broker 运营、Enterprise、Lender 后台工作流。**原则**：审批人由后台配置；每个步骤支持负责人、备用人、SLA 与审计；角色不能越域。

## 审批流

```text
用户提交
→ Broker 资料完整性审核
→ 企业 HR 核验员工事实
→ Broker 安全提交申请包
→ Lender 初审
→ Lender 复审/额度决定
→ 用户合同确认
→ Lender 合同证据验收
→ Lender 放款经办 + 复核
→ SMILE CAPITAL PLC 托管钱包到账
→ 用户提现/主动还款事件与异常处理
```

## 角色与权限

| 域         | 角色                | 允许操作                                           | 禁止操作                         |
| ---------- | ------------------- | -------------------------------------------------- | -------------------------------- |
| Broker     | 资料审核员          | 完整性检查、补件、催办                             | 授信、定价、合同、放款、核销     |
| Broker     | 服务费财务经办/复核 | 服务费凭证双人复核                                 | 修改贷款本息账                   |
| Enterprise | HR 核验员           | 员工身份、在职、工龄、合同状态、工资事实           | 查看费用、额度、合同、征信、钱包 |
| Lender     | 初审/复审           | KYC 结论、授信、报价、拒绝                         | 修改 Broker 原始证据             |
| Lender     | 合同/放款经办与复核 | 合同验收、放款双人审批                             | 绕过证据或自行结清               |
| Lender     | 钱包/还款异常处理   | 回调核对、托管钱包冻结/解冻建议、提现/还款异常工单 | 单人手工改余额或核销             |

## 配置能力

- 平台管理员维护部门—角色—账号、负责人、备用审批人、阈值、SLA、工作时间和语言偏好。
- 每一步仅允许当前负责人或已升级的备用人操作；不得用共享账号。
- 审批记录包含动作、前后状态、原因码、备注、操作者、时间、证据引用与审计哈希。
- 所有资金调整、放款、核销与钱包例外必须双人复核；后台不得直接“改余额”。
- V1 不存在企业财务扣款队列、工资代扣审批流或“三种回收方式”配置项。

## 队列与升级

1. 企业 HR 在提交后按 12/24/48 小时提醒与升级；仅通知本租户负责人。
2. 持牌机构审核、合同验收、放款、提现异常和还款异常均按配置 SLA 建工单。
3. 成功、拒绝、补件、放款、提现及还款结果会触发 T04 的用户通知事件。

## T05 验收

- 跨域、跨工厂、跨角色访问均返回 403 并审计。
- 一人不能同时完成放款或核销经办与复核。
- 备用人接管、超时升级、撤回、拒绝、补件与异常工单均有测试。
- 企业端永不出现持牌机构名称/编号、额度、费率、合同、钱包或完整账单。
