## 1. P0 任务分解

| 顺序 | 任务               | 代码影响                             | 最小验收                                                                |
| ---- | ------------------ | ------------------------------------ | ----------------------------------------------------------------------- |
| P0-1 | 清理旧业务模型依赖 | 状态机、DTO、fixture、页面文案       | 不再存在放款前费用阻塞、7–180 天、企业仅扣本金等新订单逻辑              |
| P0-2 | 规则与快照         | broker/lender 迁移、纯函数、规则服务 | 工厂发薪提示、15/30、一次/两次计划、钱包/还款授权/费用/分润版本不可回写 |
| P0-3 | 企业租户与角色     | Enterprise、broker API、RLS/RBAC     | HR/财务跨租户或越字段访问 403；企业财务不出现扣款、钱包或核销能力       |
| P0-4 | 用户申请与最终授权 | Mini App、broker API、证据存储       | 用户选工厂、完成 KYC、查看报价、确认还款授权说明、独立授权和签署证据    |
| P0-5 | 持牌独立审批与账务 | lender-core/API/console              | 授信/合同/放款/核销仅持牌域；经办复核分离                               |
| P0-6 | 两域事件链         | Outbox/Inbox、契约、Stub             | mTLS/签名接口、幂等、乱序、重试、死信与最小字段全部测试                 |
| P0-7 | 服务费、钱包与还款 | 三端页面、钱包/还款事件、异常工单    | 放款后 D+1/2/3 服务费；托管钱包到账、提现、主动授权还款；异常不自动核销 |
| P0-8 | UAT 与运营         | UAT fixture、SOP、审计报表           | 申请→核验→审批→合同→放款→钱包到账→提现→收费→还款→核销→分润受控演练通过  |

## 2. 编码规则

- 不重写认证、安全门禁、金额类型、审计基础和两域项目结构；在现有基础上替换旧业务模型。
- 当前未提交的旧 M0-02 逻辑必须逐项比对 P0-1；不符合规范的迁移、状态或测试须替换，不能仅改文案。
- 先迁移/纯函数/测试，再路由与 UI；任何新表需要追加式事实表、字段脱敏、权限和审计设计。
- 默认关闭真实银行/支付/征信/活体/电子签 SDK 和岗位个人激励；可实现托管钱包、提现、主动授权还款的受控 Stub 与契约，但不得再实现工资代扣或三种回收方式配置。

## 3. 每个任务的提交前验证

```powershell
pnpm format:check
pnpm typecheck
pnpm test
pnpm --filter @payease/user-mini-app run build
pnpm --filter @payease/broker-api run test:integration
```

同时通过：Semgrep、Gitleaks、金额守卫、许可证守卫、跨租户/跨角色 403、非法状态迁移、幂等事件、审计不可改、maker-checker、三语文案和像素级 Mini App 测试。

## 4. 绝对禁止

- 不共享两域数据库、KMS、对象桶、Redis、Cookie、管理员账号或内部主键。
- 不让 KhmerX/企业端修改授信、利率、合同、放款、贷款核销或征信结果。
- 不把融资居间服务费混入本金、利息、托管钱包余额或主动授权还款指令。
- 不导出完整证件/账户/联系人，不提交真实 PII、合同、视频、签名、密钥或生产证书。
- 不在法务、银行、供应商和生产变更批准前启用真实外部接口。
