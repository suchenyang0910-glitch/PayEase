# Trae 编码任务：V1 企业协作、回收与结算

> **版本**：V1.0｜**状态**：开发冻结基线；合同文本、工资扣款合法性、银行代扣能力及分润税务仍须在生产启用前由持牌机构与柬埔寨法务签字。
> **范围**：KhmerX 助贷域、企业 HR/财务端、持牌机构域和两域接口。
> **本文件优先级**：对“回收方式、企业协作、分润”覆盖旧文档中的相反表述；其他产品、隐私和隔离规则继续以 `V1_SALARY_LOAN_PRODUCT_RULES.md`、`V1_两域薪资贷_任务单与里程碑计划.md` 为准。

## 1. 不可突破的架构边界

```text
KhmerX 助贷域
├─ PayEase Telegram Mini App：申请、协议/授权、状态、账单投影、提醒、服务费
├─ KhmerX Operations：资料完整性、企业催办、服务费复核、客服与工单
└─ KhmerX Enterprise：工厂资料、员工花名册、事实核验、工资回收执行回填
       │ 版本化 API + mTLS + 签名 + Outbox/Inbox
       ▼
持牌机构域
├─ KYC/征信、授信、利率、最终合同、放款
└─ 本息账、核销、逾期、最终投诉结论
```

- KhmerX、企业 HR/财务均不得决定额度、利率、放款、核销、逾期结论或修改持牌合同。
- 企业端仅见本工厂租户；不得见完整证件、联系人、银行卡、内部评分、持牌机构内部资料。
- KhmerX 融资居间服务费与持牌机构贷款本息必须独立合同、账单、收款账户、凭证、审批和对账。
- 所有金额 API 均使用 `{ amountMinor: string, currency: "USD" }`；禁止 `number`。

## 2. 已冻结业务规则

### 2.1 产品与还款计划

- 每笔单笔薪资贷期限仅 `15` 或 `30` 个自然日；起算日为持牌机构确认的 `disbursedAt`。
- 用户可选择一次还清，或在关联工厂连续两个已启用发薪节点分两次还清；服务端生成并在合同前冻结计划。
- 两次还款：第一期本金与总利息各取 `floor(总额 ÷ 2)`，剩余最小货币单位全部进入第二期。
- 每个工资发薪节点后有 3 个自然日缓冲；节假日顺延、逾期规则由持牌机构和法务冻结后启用。

### 2.2 工厂与员工资料

- 一个工厂对应一个 `employerTenantId`。
- 平台管理员创建工厂时配置：法定/显示名称、工厂编号、地址、对接人、收款主体、可选发薪日（1 或 2 个，具体日或月末）、允许回收方式、费率与分润规则版本。
- 工厂定期导入员工花名册：工号、姓名、加密证件匹配值、入职时间、在职状态、授权范围内的工资资料。
- 用户选择工厂并提交姓名、身份证/护照号；仅在该租户内以证件 HMAC 主匹配，姓名和工号仅作辅助校验。

### 2.3 三种本息回收方式

| 枚举                         | 何时可选                 | 执行主体      | 关键前置                                     | 回填结果                        |
| ---------------------------- | ------------------------ | ------------- | -------------------------------------------- | ------------------------------- |
| `EMPLOYER_PAYROLL_DEDUCTION` | 工厂启用且该订单已授权   | 企业财务      | 用户逐笔工资扣款授权、合同快照、法务启用标志 | 已扣 / 部分扣 / 未扣 + 执行凭证 |
| `LENDER_DIRECT_DEBIT`        | 持牌机构与银行能力已启用 | 持牌机构/银行 | 用户本人账户独立授权、账户校验、持牌配置     | 成功 / 失败 / 撤销 / 重试耗尽   |
| `BORROWER_MANUAL_PAYMENT`    | 默认兜底                 | 用户          | 持牌指定收款账户与账单                       | 待核销 / 已核销 / 退回          |

规则：工厂配置的是“允许回收方式”和默认建议，用户在最终合同前选择具体方式；每笔订单写入不可改的 `repaymentMethodSnapshot`、授权版本、收款主体、回收计划与规则版本。未满足前置条件必须回退至用户主动付款，不能静默改为工资扣款或银行代扣。

### 2.4 融资居间服务费

- 正式名称：`融资居间服务费 / Financing Brokerage Remuneration / ប្រាក់កម្រៃសេវាអន្តរការហិរញ្ញវត្ថុ`。
- 费率优先级：工厂有效版本优先，平台默认版本兜底；默认月费率 10.5%，但必须版本化而非硬编码。
- 计算：`approvedPrincipal × applicableBrokerageMonthlyRate ÷ 30 × actualDays`。
- 实际放款成功后才建立应收；D+1、D+2、D+3 提醒，D+3 最晚支付日；用户向 KhmerX 指定账户单独支付并上传凭证，KhmerX 财务经办/复核接受。
- 绝不进入持牌本息回收、企业工资扣款清单或银行 Direct Debit 指令。

### 2.5 工厂协作补偿与个人激励边界

工厂可选择一种有效的分润规则，规则须具备有效期、版本、批准人、收款主体与结算周期：

1. `FIXED_MONTHLY_USD`：每月固定 USD 金额；须明确无有效订单时是否仍结算。
2. `DISBURSED_PRINCIPAL_RATE`：实际放款本金 × 分润系数；拒贷、未放款、服务费未确认或已退款订单不计入。

KhmerX 只向工厂书面授权的收款主体结算。HR/财务岗位激励作为**可选、默认关闭**的企业内部安排：可按核验时效、资料准确性和回填及时性评估；不得以单个员工获批、放款、拒绝、逾期或催收结果计算。不得在系统中保存 HR/财务个人的收款账户或由 KhmerX 向其直接付款。

## 3. 完整业务流程

```text
1. 平台管理员创建工厂、租户、发薪节点、允许回收方式、费率/分润规则（均版本化）
2. 工厂受控导入花名册；HR/财务账户仅绑定本租户
3. 用户从 Telegram 登录，选择语言、工厂，填写 KYC 与申请资料
4. 用户确认服务协议、数据处理与企业核验授权，提交申请
5. KhmerX 资料完整性审核；企业 HR 核验身份、在职、合同状态、工龄与工资事实
6. KhmerX 通过受控接口向持牌机构推送申请包；持牌机构独立审批
7. 持牌机构回传获批要约、合同和允许的还款方式；用户查看完整费用与账单计划
8. 用户签最终合同，并按选择回收方式签署必要的单独授权；采集手机签名与确认视频
9. 持牌机构双人审批、人工放款；`disbursedAt` 回传后冻结实际天数和账单
10. KhmerX 建立独立居间服务费应收、D+1/D+2/D+3 提醒与财务双人复核
11. 每个还款节点 T-3/T-1/T 提醒；按订单回收方式执行本息并将结果回传持牌机构
12. 持牌机构双人核销；部分/未扣或代扣失败创建异常工单；完成后结清并生成对账记录
13. 工厂结算周期结束后，按有效版本与已满足结算条件的订单生成分润对账单，经双人审批后结算
```

## 4. Trae 实施任务

### P0-A：规则、数据与纯函数

- 建立不可变 `EmployerPayrollRuleVersion`：发薪节点、允许回收方式、默认方式、法务启用状态、生效期。
- 建立不可变 `RepaymentMethodSnapshot` 和 `RepaymentPlanSnapshot`；禁止规则修改回写历史订单。
- 建立 `EmployerRevenueShareRuleVersion`：规则类型、固定金额或比例、结算周期、收款主体引用、审批记录。
- 增加纯函数与 fixture：15/30 天、一次/两次计划、奇数分币进入第二期、三种回收方式前置校验、D+1/D+2/D+3、T-3/T-1/T 与工资日后 3 天缓冲。

### P0-B：权限与企业端

- 平台管理员：维护工厂、发薪节点、允许回收方式、对接人、工厂收款主体和规则版本。
- HR：仅核验员工身份/在职/合同/工龄/工资事实；不可处理工资扣款、不可浏览金融字段。
- 企业财务：仅在订单为 `EMPLOYER_PAYROLL_DEDUCTION` 且授权有效时，下载最小化扣款清单，回填已扣/部分扣/未扣与凭证。
- 所有租户、角色、字段、下载与回填均需 403 测试及不可变审计。

### P0-C：用户端与合同证据

- 最终要约页展示三种允许回收方式；未启用/无授权方式不可选。
- 选择工资扣款或银行代扣时，展示独立授权文本、语言、版本、撤销/变更处理提示；不得默认勾选。
- 合同前展示本金、利息、融资居间服务费、实际到账、每期本息、回收方式、工资节点、缓冲期与规则版本。
- 签名和最终合同/工资扣款授权确认视频分别保存，均与合同哈希、会话、语言、挑战词、时间和操作者关联。

### P0-D：持牌域与跨域接口

- 持牌域为还款计划、收款账户、银行代扣、核销与异常的唯一权威域；KhmerX 仅投影用户必要状态。
- 事件必须有 `eventId`、来源域、幂等键、订单外部引用、规则/计划快照版本、签名、时间窗口。
- KhmerX 向持牌域回传企业工资扣款事实；持牌域回传银行代扣和核销结论。禁止跨域直读库。

### P1-E：工厂分润结算

- 生成仅含结算必要数据的工厂对账单；不得向 HR/财务展示其他员工的贷款细节。
- 分润生成、调整、退款冲回和结算均实行经办/复核分离与追加式审计。
- “HR/财务岗位激励计划”仅显示为关闭状态和治理说明；不实现个人付款。

## 5. 强制验收

1. 三种回收方式中任一前置条件缺失，服务端拒绝并不改变订单方式。
2. 工厂 A 的 HR/财务绝不能查看或回填工厂 B 的任何订单。
3. 企业财务导出不含完整身份证、联系人、银行卡、费率、居间服务费、持牌合同或内部风控字段。
4. 任何企业回填、银行回调、用户凭证均不能直接将订单核销；只可由持牌机构双人核销。
5. 服务费不得出现在工资扣款或银行代扣指令，且放款失败不得生成服务费应收。
6. 分润只能计入满足有效规则、实际放款、费用确认且未退款的订单；重复任务/回调不得重复结算。
7. 所有金额以最小货币单位字符串传输；所有财务、核销、分润与授权事实仅追加写入。
8. 类型检查、单元测试、跨租户/跨角色权限测试、状态机非法迁移、审计不可改、三语文案及安全门禁全绿后，方可提交审查。

## 6. 禁止项

- 不接真实银行 Direct Debit、支付、HRIS、征信、活体或电子签 SDK，直至供应商、法务和安全审批完成。
- 不将服务费从放款本金扣除；不混入贷款本息或任何自动扣款指令。
- 不允许 HR/财务决定授信、利率、合同、放款、核销或访问不属于其职责的字段。
- 不在代码、fixture、日志或仓库提交真实个人资料、银行账户、视频、签名、证件、密钥或合同。
- 不默认启用工资扣款、银行代扣或 HR/财务个人激励。
