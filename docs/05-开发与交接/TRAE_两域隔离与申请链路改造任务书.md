# Trae 任务书：两域硬隔离与薪资贷申请链路改造

> **任务级别**：P0
> **适用范围**：PayEase Mini App、KhmerX 助贷后台、企业 HR 核验端、助贷域 API。
> **不在本任务范围**：持牌机构风控、征信、最终额度、放款、收款、贷后系统的实现；这些仅由持牌机构独立域实现。

## 1. 目标与不可突破边界

将当前系统收敛为两个物理隔离域：

```text
KhmerX 助贷域（独立仓库 / VPS / 数据库 / KMS）
├─ Telegram Mini App
├─ 助贷运营后台
├─ 企业 HR 核验端
└─ broker-api
         │ mTLS + 请求签名 + 版本化 API
         ▼
持牌机构域（独立仓库 / VPS / 数据库 / KMS）
├─ lender-api
├─ lender-console
└─ lender-core
```

以下规则不得被代码、Mock、部署脚本或临时账号绕过：

1. 助贷域不得查询征信、设置最终额度/利率、生成最终借款合同、执行持牌贷款本金放款或收取贷款本金/利息，亦不得修改持牌机构账单。助贷域仅可按已确认、版本化的服务协议收取自身服务费。
2. 持牌机构域不得直接联系用户或企业 HR；只接受助贷域推送的申请包，并向助贷域回传标准化事件。
3. HR 账号只能访问本企业 `employerTenantId` 下的申请人基础核验信息；不得访问身份证原文、银行卡、联系人、额度、合同、账单、逾期或风控结论。
4. 助贷域和持牌机构域禁止共享数据库、对象存储桶、KMS 密钥、管理员账户、Cookie、会话或内部主键。
5. 金额传输统一为 `{ amountMinor: string, currency: "USD" | "KHR" }`；禁止 JavaScript `number` 参与金额计算或接口传输。

## 2. 用户端文案与展示规则：弱化持牌机构

### 2.1 可使用的用户文案

| 场景         | 用户端推荐文案              |
| ------------ | --------------------------- |
| 申请提交后   | `资料已提交，正在核验中`    |
| 助贷资料审核 | `资料审核中`                |
| 企业核验     | `正在确认您的在职信息`      |
| 已推送机构   | `额度审核中`                |
| 机构要求补件 | `需要补充资料`              |
| 最终结果     | `额度审核结果已更新`        |
| 放款阶段     | `放款处理中` / `款项已发放` |
| 账单阶段     | `还款计划` / `待还金额`     |

禁止在首页、申请页、普通状态页和 HR 端频繁展示“持牌机构”“机构风控”“征信”“拒贷规则”等词。

### 2.2 不得弱化或隐藏的法定披露

在下列页面必须展示由法务确认的正式持牌主体、合同版本和费用主体：

1. 最终借款合同确认页；
2. 费用确认页；
3. 争议/投诉处理说明页；
4. 放款确认与账单详情页（按法务确认的披露范围）。

不得以“合作金融机构”等泛称替代合同中的法定主体。

## 3. Trae 开发任务拆分

### T0：规则源文档与配置冻结

现有 `docs/01-产品与业务/薪资贷-产品方案与PRD.md` 仍包含“V1 不做企业代扣”的历史表述；在写业务代码前，必须更新为当前已确认的“企业自行执行工资扣款、但仅在最终合同和单独授权后生效”。

同时冻结以下待法务确认的配置对象，而不是将数值或合同文案散落硬编码：

- 助贷服务费、利息、支付前置条件、退款/未放款处理规则；
- 15/30 天产品期限和到期日顺延规则；
- 最终借款合同、助贷服务协议、企业工资代扣授权、确认视频文案的 `version / language / effectiveAt`；
- 企业扣款执行主体、文件留存期限与有权查看角色。

**已确认的 V1 商业口径（必须作为可版本化配置实现）**

| 项目         | V1 规则                                                                                                                                                                         |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 产品         | 单笔申请；严格匹配工厂已配置的一个或两个工资发放节点                                                                                                                            |
| 助贷服务费   | 工厂有效月费率优先、平台默认月费率兜底；实际放款后由用户向 KhmerX 指定账户支付，D+1/D+2/D+3 提醒，D+3 到期                                                                      |
| 持牌机构利息 | 月利率 1.5% 默认值；用户在每个还款节点向持牌指定账户支付本期利息，不得混入 KhmerX 服务费收入                                                                                    |
| 按期计算     | 借款总天数为实际放款日至最后一个冻结发薪节点；费用/利息使用 `本金 × 月费率 ÷ 30 × 实际天数`。金额最小单位、舍入模式、费率来源与展示口径必须由规则版本明确，禁止前端作为最终计算 |
| 回收方式     | 每笔在合同前冻结企业工资扣款、持牌机构本人账户代扣或用户主动付款之一；工资扣款仅在工厂启用、用户逐笔授权及法务启用条件满足时可执行本息；一次还清或两期平均本息，余数归第二期    |
| 期限起算     | 以持牌机构回传的实际放款成功时间为准；由持牌域生成冻结发薪节点计划；每个节点有工资日后 3 个自然日缓冲期                                                                         |
| 还款不足     | 允许已扣 / 部分扣 / 未扣；部分或未扣自动进入人工处理，不允许前端或 HR 自行核销                                                                                                  |

**费用披露要求**：合同/账单必须同时显示融资居间服务费、适用费率来源、服务费 D+3 最晚支付日、利息、本金、一次/两次还款节点、本期本息、规则版本及“最终以法务冻结的合同与费用披露为准”。不得将居间服务费包装成放款本金扣除。

**KhmerX 收费名称**：10.5% 月费率的用户端、合同与账务展示统一为“融资居间服务费 / Financing Brokerage Remuneration / ប្រាក់កម្រៃសេវាអន្តរការហិរញ្ញវត្ថុ”，技术枚举为 `FINANCING_BROKERAGE_REMUNERATION`。每笔确认必须列明服务事项、费率、应付金额、收款主体、支付路径和 `feeRuleVersion`；不得以该名称宣称无需监管或当然不属于融资成本。

**验收**：PRD、费用结算规则、三语协议清单、状态机和接口契约中的同一规则版本一致；未获法务批准的配置不能在生产环境启用。

### T1：助贷域申请状态机与角色边界

**改动目标**

- 将 `BROKER_APPROVED` 等容易误解为信贷批准的状态改为 `BROKER_PRECHECK_PASSED`（助贷资料核验通过）。
- 新增/统一：`LENDER_PACKAGE_SENT`、`LENDER_REVIEWING`、`LENDER_MORE_INFO_REQUIRED`、`LENDER_DECISION_RECEIVED`、`READY_FOR_DISBURSEMENT`、`DISBURSEMENT_EXCEPTION`、`DISBURSED`、`BROKERAGE_REMUNERATION_DUE`、`BROKERAGE_REMUNERATION_OVERDUE`、`PAYROLL_COLLECTION_PENDING`、`COLLECTION_EXCEPTION`、`PAID_OFF`。不得再使用 `PRE_DISBURSEMENT_PAYMENTS_*` 作为放款门禁。
- 持牌机构最终决策仅由回调事件写入，不允许助贷后台直接编辑。

**验收**

- 助贷后台无法在任何接口或页面上提交“最终额度/利率/放款成功”写操作。
- 每次状态变化含 `eventId`、操作者、来源域、原因码、时间和前一状态。
- 非法状态迁移返回稳定错误码并写审计事件。

### T2：Mini App 借款申请第二屏

**页面字段**

- 申请金额：USD 10–500，滑块、手输、快捷金额；金额使用字符串最小单位保存。
- 还款选择：下一工资节点一次还清，或连续两个工资节点归还；只可由服务端按工厂有效发薪节点生成。
- 合规用途：日常生活、医疗、教育、家庭紧急支出、其他合规用途；服务端白名单二次校验。
- 预估区：申请金额、适用居间费率来源、预估居间服务费、预估利息、放款本金、一次/两次工资节点、本期本金/利息、服务费 D+3 最晚支付日；全部标注“以审核结果及最终合同为准”。
- 协议勾选：服务协议、个人信息授权、企业核验授权、风险告知。

**验收**

- 金额、期限、用途、必选授权任一缺失时 CTA 不可提交。
- 申请页不出现“保证放款”“秒过”“无条件”“最终授信”等文案。
- 提交后的用户状态为“资料已提交，正在核验中”，而非“已获批”。
- 三语 `km/en/zh-CN` 完整覆盖；用户首次选择的语言在后续登录中恢复。

### T3：KYC 采集、拍摄与人工活体复核

**V1 实现**

- 收集身份证/护照照片、用户自拍/短活体采集视频、申请资料所需文件。
- 前端只采集和上传；不做本地人脸比对、不调用外部活体 SDK、不在浏览器持久化媒体文件。
- 助贷后台建立 `LIVENESS_MANUAL_REVIEW` 队列，由两名不同权限人员执行初审/复核。

**安全验收**

- 上传使用短时、单用途上传凭据；文件不公开，服务端保存 SHA-256、MIME、大小、来源会话和扫描状态。
- 原始文件加密存储；日志、通知、HR 页面不得输出照片 URL、证件原文或活体视频。
- 活体失败/无法拍摄进入人工补件，禁止自动拒贷。

### T4：企业 HR 核验端

**可见字段**：姓名、企业员工号（若有）、在职状态、工资区间/确认值、入职日期/工龄、劳动合同状态、核验意见。

**不可见字段**：身份证/护照、银行卡、联系人、用户自拍或视频、用途、金额、费用、额度、合同、账单、还款、征信和风控结论。

**验收**

- 每个查询都强制 `employerTenantId`；跨租户一律返回 403。
- HR 核验结果为 `MATCHED / NOT_MATCHED / NEED_MORE_INFO`，不能替代授信判断。
- 提交后 12/24/48 小时自动生成核验催办任务；催办内容不泄露贷款金额和费用。

### T5：放款后融资居间服务费

**流程**

```text
持牌机构实际放款成功并回传 DISBURSED
→ Broker 按工厂覆盖/平台默认费率冻结居间服务费应收
→ D+1 / D+2 / D+3 三语提醒用户向 KhmerX 指定账户支付
→ 用户上传凭证
→ 助贷双人复核支付凭证
→ 助贷域记录 BROKERAGE_REMUNERATION_PAYMENT_ACCEPTED
```

**规则**

- 支付前必须显示金额、收款主体、支付方式、退款/未放款处理规则、规则版本。
- 居间服务费支付不是放款指令，也不影响已完成的放款事实。
- 付款凭证仅助贷财务/复核角色可见；HR 和普通客服不可见。
- 所有人工确认要求经办人与复核人不同，并有不可修改审计记录。
- D+3 未完成验收进入 `BROKERAGE_REMUNERATION_OVERDUE`；该状态不得改写放款、授信、合同或持牌账务状态。操作、凭证、审批人与时间均须审计留痕。

### T6：最终合同、工资代扣授权与确认视频

此任务只实现助贷域的展示、采集、证据保全和回传；最终借款合同由持牌机构域生成和签署状态回传。

- 合同确认页展示法务批准的主体、合同 PDF 哈希、语言、版本、最终费用和还款计划。
- 用户可在手机签名；签名图与合同哈希、会话、时间、语言版本共同保存。
- 用户录制 5–10 秒确认视频，读取当前语言固定确认文案和一次性挑战词。
- 视频仅在合规/争议/受授权复核角色可查看；禁止企业 HR 和普通运营列表播放。
- 企业工资扣款授权仅在最终还款计划确定后出现；不得在初始申请阶段默认勾选。
- 企业按工厂配置的固定工资日使用受控后台导出扣款清单，并回填 `COLLECTED / PARTIALLY_COLLECTED / NOT_COLLECTED`；清单只能包含执行扣款所必需的员工引用、授权引用、本金金额、到期日和处理状态。
- KhmerX 客服可以答复费用、还款计划和工资扣款的事实与流程，但不得修改额度、利息、合同、放款或核销结果；需要变更的一律创建工单并交由有权方处理。

### T7：跨域连接器

- 按 `docs/06-接口与集成/助贷域-持牌机构接口标准V1.md` 实现 Broker Outbox、Lender Callback Inbox、签名验证、幂等、重试和死信工单。
- 开发与测试阶段只使用本地 Lender Stub 与 fixture；真实 URL、证书、签名私钥、银行接口配置不进入仓库。

### T8：持牌机构域信用信息查询连接器预留

**定位**：连接器仅存在于持牌机构域。KhmerX 助贷域、Mini App、助贷运营后台和企业 HR 端均不得发起、代理、缓存或查看征信查询。

柬埔寨国家银行（NBC）负责监管信用报告体系；实际信用信息服务接入主体、成员资格、查询 API/门户形式、授权文本和数据报送规则，以持牌机构与受监管征信公司（例如 CBC）的正式接入材料为准。禁止在代码中假定存在公开的“NBC 征信 API”。

**接口骨架**

```text
lender-core/
└─ credit-reporting/
   ├─ CreditReportingProvider.ts       # 领域接口，不含真实供应商 SDK
   ├─ CbcCreditReportingAdapter.ts     # 仅预留，默认禁用
   ├─ CreditInquiryConsentGuard.ts      # 授权、用途与期限检查
   ├─ CreditReportEvidenceStore.ts      # 加密证据与哈希
   └─ CreditInquiryAudit.ts             # 不可修改审计事件
```

**强制规则**

- 查询前必须验证持牌机构成员资格、用户书面/电子授权版本、查询目的“信用资质评估”以及授权有效期。
- 查询请求只使用最终所需身份字段；不得将完整征信报告回传给助贷域。
- 助贷域最多接收 `LENDER_REVIEWING / MORE_INFORMATION_REQUIRED / DECISION_AVAILABLE` 等业务状态和可展示原因码。
- 原始报告、查询结果、供应商交易号、凭据和审计证据只保存于 `lender_db` 与持牌机构加密存储。
- 任何查询、失败、重试、人工查看、导出均须写入持牌机构审计域；不允许在浏览器日志、客服工单或企业 HR 页面出现。

**验收**

- 助贷域代码库没有征信供应商 URL、SDK、密钥、请求 DTO 或原始报告字段。
- Lender Stub 可验证“无授权拒绝、授权过期拒绝、用途不匹配拒绝、重复查询幂等、报告不跨域回传”。
- 真实连接器默认 `disabled`；仅在持牌机构完成成员资格、法务授权文本、供应商安全评审、证书交换和生产变更审批后启用。

## 5. 合并门禁

- 每任务必须有单元测试、权限测试、三语文案测试和审计事件测试。
- 不提交真实 PII、Bot Token、支付凭证、合同、视频、身份证照片、证书或私钥。
- 所有 API 变更同时更新契约、错误码与 fixture。
- 真实持牌机构接口的启用条件：法务文本冻结、双方 SOW/DPA、mTLS 证书交换、联调验收、回滚与异常处置演练完成。
