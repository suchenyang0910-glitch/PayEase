# KhmerX × PayEase V1：两域薪资贷任务单与里程碑计划

> **版本**：V1.0｜**日期**：2026-08-20｜**执行对象**：Trae 编码、Codex 审查与发布。
> **目的**：以“KhmerX 助贷域 + 持牌机构域”物理硬隔离为基线，交付首家工厂试点可运行的单笔薪资贷人工运营闭环。
> **优先级规则**：P0 未通过，不得进入下一里程碑；P1 可在同一里程碑内排期处理；P2 不得影响试点上线。

## 1. 已冻结的 V1 业务范围

### 1.1 参与方与边界

```text
用户（Telegram Mini App）
  → KhmerX 助贷域：资料、企业核验、服务费复核、通知、客服、运营协调
  → 持牌机构域：征信、额度、借款合同、放款、核销、贷款账与最终投诉结论

企业 HR 端属于 KhmerX 助贷域：仅核验本企业员工的在职与工资相关字段。
```

- 一座工厂对应一个 `employerTenantId`；HR 账号只可见本企业范围。
- V1 为**单笔借款**：USD 10–500；还款严格对齐工厂发薪节点，用户选择下一节点一次还清或连续两个节点归还本金。
- 用户先完成服务协议、数据授权、企业核验授权；额度结果后完成借款合同、费用确认、工资代扣授权、手机签名与确认视频。
- 费用支付、放款、工资扣款、核销均允许人工操作，但必须有角色分离、凭证、审计和幂等记录。
- 期限从持牌机构回传的 `disbursedAt` 开始；企业按工厂配置工资日仅扣贷款本金。

### 1.3 KhmerX 收费名称与展示基线

KhmerX 的 10.5% 月费率在 V1 统一使用下列名称；技术枚举使用 `FINANCING_BROKERAGE_REMUNERATION`，不得继续以模糊的 `SERVICE_FEE` 混同持牌机构利息：

| 语言    | 正式展示名称                       |
| ------- | ---------------------------------- |
| 中文    | 融资居间服务费                     |
| English | Financing Brokerage Remuneration   |
| ខ្មែរ   | ប្រាក់កម្រៃសេវាអន្តរការហិរញ្ញវត្ថុ |

每笔费用确认必须同时展示：服务事项摘要、费率与计算方式、应付金额、收款主体、支付路径、`feeRuleVersion`、合同/授权版本及投诉入口。名称用于准确描述 KhmerX 的撮合服务，不得在产品页面或合同中表述为“无需监管”“不属于融资成本”或其他未获法务确认的结论。

### 1.2 V1 不做的事项

- 自营资金池、KhmerX 自行授信、自动放款、自动核销、自动银行卡扣款；
- 真实银行、支付、HRIS、外部活体、电子签或征信 SDK 的直接接入；
- 共享数据库、共享对象存储、共享 KMS、共享管理员身份或跨域读库；
- 消费分期、企业/供应商融资、多机构路由等未来产品。

## 2. 里程碑总览

| 里程碑 |   建议周期 | 目标                             | 退出条件                                     |
| ------ | ---------: | -------------------------------- | -------------------------------------------- |
| M0     |    第 1 周 | 两域基线、产品规则和数据模型冻结 | 规则、状态机、权限矩阵、迁移设计审查通过     |
| M1     |  第 2–3 周 | KhmerX 助贷域核心与用户申请      | Telegram 会话、KYC、申请、审计、费用试算通过 |
| M2     |  第 4–5 周 | 企业 HR 与助贷运营闭环           | 租户隔离、核验催办、补件、双人复核通过       |
| M3     |  第 6–7 周 | 持牌机构独立域与人工审批         | 组织/RBAC、额度、合同、放款/核销审批通过     |
| M4     |    第 8 周 | 两域受控导入与事件联调           | mTLS/签名 Stub、幂等、异常回调演练通过       |
| M5     | 第 9–10 周 | 四端 UAT、试运营与发布           | 人工运营闭环、权限安全、对账、上线清单通过   |

**排期前提**：一名工程负责人使用 Trae 编码、Codex 审查；复杂缺陷、合同法务冻结、首家工厂资料准备不计入以上纯开发工期。若持牌机构独立团队不与 KhmerX 并行开发，M3 与 M4 可能额外增加 2–3 周。

## 9. 每日执行节奏

| 时间点 | Trae                                          | Codex                                   |
| ------ | --------------------------------------------- | --------------------------------------- |
| 开始前 | 读取本任务、相关契约、现有测试，列出影响文件  | 检查边界、依赖与任务是否可开工          |
| 编码中 | 每完成一个原子任务先跑定向测试                | 并行审查任务输出、补充验收场景与风险    |
| 提交前 | 输出变更、迁移、权限影响、测试结果、diff 统计 | 运行全量门禁与安全检查，确认无越权修改  |
| 发布前 | 不自行 commit/push/deploy                     | 复核、提交、推送、CI 通过后执行受控部署 |

## 10. 全局验收门禁

```powershell
pnpm format:check
pnpm typecheck
pnpm test
pnpm --filter @payease/user-mini-app run build
pnpm --filter @payease/broker-api run test:integration
```

还必须通过：Semgrep、Gitleaks、金额守卫、许可证检查、跨租户/跨角色 403、状态机非法迁移、审计不可改、双人复核分离、三语文案及像素级小程序验收。

## 11. 上线前必须由业务/法务确认的独立门禁

以下事项不阻塞编码，但**阻塞生产启用**：费用性质和披露、持牌机构利息收款/代收安排、退款时限、工资代扣授权文本、节假日顺延、合同及电子签署证据、数据留存与调阅审批、首家工厂和持牌机构的正式 SOW/DPA。
