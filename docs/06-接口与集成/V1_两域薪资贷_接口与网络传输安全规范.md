# V1 两域薪资贷接口与网络传输安全规范

**版本**：V1.0｜**状态**：开发基线｜**关联总则**：[规范基线](../00-导航与治理/V1_两域薪资贷_规范基线.md)

## 1. 传输与身份认证

- 仅 HTTPS/TLS 1.2+；生产跨域调用必须 mTLS，双方证书独立、90 天轮换、撤销可用。
- 每个请求签名 `Ed25519` 或经双方批准的等效方案；签名覆盖 method、path、body SHA-256、timestamp、nonce、keyId。
- 允许时钟偏差最多 300 秒；nonce 在接收域存储并防重放；密钥、证书、私钥只在对应域秘密管理服务中保存。
- API Gateway 仅开放明确 allowlist、速率限制、WAF 规则；管理接口永不直接公网暴露。

## 2. 统一消息信封

```json
{
  "eventId": "evt_...",
  "eventType": "LENDER_DECISION_AVAILABLE",
  "eventVersion": "v1",
  "sourceDomain": "LENDER",
  "occurredAt": "2026-08-21T00:00:00Z",
  "idempotencyKey": "...",
  "externalApplicationRef": "app_ext_...",
  "payload": {},
  "payloadSha256": "..."
}
```

接收方先校验 mTLS、签名、nonce、时间窗、schema 和幂等键，再写 Inbox 和 Outbox；业务处理异步、可重试。HTTP 成功只表示收到，不表示业务状态已经生效。

## 3. 允许的跨域事件

| 来源          | 事件                                                                                                       | 最小化内容                                                         |
| ------------- | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| KhmerX → 持牌 | `APPLICATION_PACKAGE_SUBMITTED`                                                                            | 外部订单引用、经授权的申请加密包引用、合同/授权版本、请求证据 Hash |
| 持牌 → KhmerX | `LENDER_APPLICATION_RECEIVED`、`LENDER_MORE_INFO_REQUIRED`、`LENDER_DECISION_AVAILABLE`                    | 状态、可展示原因码、要约/合同安全引用；无征信原文                  |
| KhmerX → 持牌 | `CONTRACT_EVIDENCE_SUBMITTED`                                                                              | 证据包 Hash、授权引用、签署证据引用                                |
| 持牌 → KhmerX | `DISBURSEMENT_CONFIRMED`、`WALLET_STATUS_CHANGED`、`WITHDRAWAL_STATUS_CHANGED`、`REPAYMENT_STATUS_CHANGED` | 实际放款时间、钱包投影、提现状态、还款/核销状态                    |

融资居间服务费、工厂分润和 HR/财务运营信息均不进入持牌贷款账事件，除非双方 SOW 明确最小化字段与用途。

## 4. 钱包、提现与主动还款接口标准

以下接口属于持牌机构域权威接口。网络边界必须固定为：

```text
PayEase Mini App
-> KhmerX 创建一次性钱包操作跳转
-> 用户打开 SMILE 受控钱包/支付页
-> 在 SMILE 域完成支付密码、提现或银行授权
-> SMILE 验签回调并更新账务
-> 持牌 -> KhmerX 发送状态投影事件
-> PayEase 刷新钱包、提现或还款状态
```

强制规则：

- Mini App 不得直连 `lender` 域资金 API。
- KhmerX 不得代理支付密码、银行卡令牌、OTP、银行授权参数或通道回调参数。
- 用户侧涉及钱包、提现、银行授权还款的敏感操作，必须在 SMILE 受控页面或其同域后端完成。
- KhmerX 只负责创建一次性跳转、展示受控状态投影与接收持牌域状态事件，不得代替持牌域执行业务确认。

### 4.0 KhmerX 创建一次性钱包操作跳转

`POST /v1/broker/wallet-operation-jumps`

用途：Mini App 向 KhmerX 助贷域申请一次性跳转，由 KhmerX 创建并返回 SMILE 受控钱包页地址。该接口是 Mini App 发起提现或还款操作的唯一入口。

最小请求字段：

```json
{
  "requestId": "req_wallet_jump_001",
  "externalApplicationRef": "app_ext_001",
  "operationType": "WITHDRAWAL",
  "idempotencyKey": "idem_wallet_jump_001"
}
```

最小响应字段：

```json
{
  "walletOperationJumpRef": "woj_001",
  "walletOperationUrl": "https://smile.example/...",
  "expiresAt": "2026-08-21T00:15:00Z"
}
```

规则：

- `operationType` 只允许 `WITHDRAWAL`、`REPAYMENT`.
- KhmerX 创建跳转时不得接收、保存或决定提现金额、收款银行卡、支付密码、还款金额或银行通道；这些敏感输入只能在 SMILE 受控钱包页内完成。
- `WITHDRAWAL` 的金额、银行卡选择与支付密码仅能在 SMILE 页面录入；`REPAYMENT` 的金额与通道只能由 SMILE 根据冻结还款计划、当前账务和授权能力生成。
- `walletOperationUrl` 必须为短时、单次、已签名跳转链接。
- `walletOperationUrl` 只允许指向 SMILE 预登记的 HTTPS 可信域名；不得返回任意域名、明文 HTTP 或可拼接开放跳转地址。
- 跳转链接必须绑定 Telegram 受控用户、`externalApplicationRef` 或 `externalWalletRef`、`operationType` 与 `walletOperationJumpRef`；不得转发给其他用户复用。
- 跳转链接一经使用必须立即失效；过期、重复使用、用户不匹配或操作类型不匹配都必须拒绝。
- SMILE 页面打开后必须再次校验其自身用户会话、授权状态和跳转绑定信息，不得仅依赖 Broker 创建时的跳转结果。
- Broker 日志只允许记录 `walletOperationJumpRef`、目标域名、操作类型和成功/失败结果；不得记录完整 `walletOperationUrl`、查询参数、签名串或页面令牌。
- KhmerX 只能创建跳转，不得代替用户向 `lender` 域提交支付密码、银行卡令牌或银行授权参数。

### 4.1 钱包到账回调

`POST /v1/lender/callbacks/wallet-credit`

用途：支付通道或持牌资金系统确认放款已进入 SMILE CAPITAL PLC 托管钱包子账本。

最小字段：

```json
{
  "eventId": "evt_wallet_credit_001",
  "externalApplicationRef": "app_ext_001",
  "externalWalletRef": "wallet_ext_001",
  "settlementRef": "settle_001",
  "creditedAmountMinor": "50000",
  "currency": "USD",
  "occurredAt": "2026-08-21T00:00:00Z",
  "payloadSha256": "..."
}
```

规则：

- 仅验签成功后才可把状态推进到 `WALLET_AVAILABLE`。
- 同一 `settlementRef` 和 `eventId` 必须幂等。
- 不返回完整银行卡号、用户实名原文或通道敏感字段。

### 4.2 提现申请与提现结果回调

`POST /v1/lender/wallet/withdrawals`

用途：SMILE 受控钱包页或其同域后端在持牌机构域内发起提现到已验证的本人银行卡。该接口为持牌域内部资金接口，不对 Mini App 或 KhmerX 开放。

最小请求字段：

```json
{
  "requestId": "req_withdraw_001",
  "externalWalletRef": "wallet_ext_001",
  "withdrawalAmountMinor": "20000",
  "currency": "USD",
  "payoutBankAccountToken": "bank_tok_001",
  "paymentVerificationRef": "pin_or_stepup_ref",
  "idempotencyKey": "idem_withdraw_001"
}
```

`POST /v1/lender/callbacks/withdrawals`

用途：支付通道回传提现成功、失败、撤销或回滚。

最小字段：

```json
{
  "eventId": "evt_withdraw_001",
  "paymentOrderRef": "po_001",
  "externalWalletRef": "wallet_ext_001",
  "withdrawalStatus": "SUCCEEDED",
  "settledAmountMinor": "20000",
  "currency": "USD",
  "occurredAt": "2026-08-21T00:00:00Z"
}
```

规则：

- 提现申请必须先冻结余额，再进入通道处理。
- `withdrawalStatus` 只允许 `PROCESSING`、`SUCCEEDED`、`FAILED`、`REVERSED`。
- 失败、取消、超时或回滚不得错误扣减可用余额。
- Mini App 不得直接调用本接口；KhmerX 也不得转发用户支付密码、银行卡令牌或通道鉴权参数来调用本接口。

### 4.3 主动还款意图与银行授权跳转

`POST /v1/lender/repayments/intents`

用途：SMILE 受控钱包页或其同域后端在持牌机构域内创建一次性的银行/支付机构授权意图。该接口为持牌域内部资金接口，不对 Mini App 或 KhmerX 开放。

最小请求字段：

```json
{
  "requestId": "req_repay_001",
  "externalApplicationRef": "app_ext_001",
  "repaymentIntentRef": "repay_intent_001",
  "repaymentAmountMinor": "12750",
  "currency": "USD",
  "channelProvider": "BANK_ABC",
  "repaymentPlanSnapshotRef": "plan_snap_001",
  "idempotencyKey": "idem_repay_001"
}
```

最小响应字段：

```json
{
  "repaymentIntentRef": "repay_intent_001",
  "authorizationUrl": "https://...",
  "authorizationExpiresAt": "2026-08-21T00:15:00Z"
}
```

规则：

- `authorizationUrl` 必须为短时、单次、已签名链接。
- KhmerX 不保存银行登录密码、OTP、完整卡号或授权页面回传敏感参数。
- 前端从银行返回只可展示“处理中”，不得自行改账。
- Mini App 只能先通过 `POST /v1/broker/wallet-operation-jumps` 获取 SMILE 跳转，不得直接调用本接口。
- KhmerX 只能看到 `repaymentIntentRef` 等受控引用，不得代理银行授权参数、OTP 或支付机构返回原文。

### 4.4 还款验签回调

`POST /v1/lender/callbacks/repayments`

用途：银行或支付机构将授权还款结果异步回传给持牌机构。

最小字段：

```json
{
  "eventId": "evt_repay_001",
  "repaymentIntentRef": "repay_intent_001",
  "paymentOrderRef": "po_repay_001",
  "externalApplicationRef": "app_ext_001",
  "repaymentStatus": "SUCCEEDED",
  "collectedAmountMinor": "12750",
  "currency": "USD",
  "occurredAt": "2026-08-21T00:00:00Z",
  "payloadSha256": "..."
}
```

规则：

- `repaymentStatus` 只允许 `PROCESSING`、`SUCCEEDED`、`FAILED`、`CANCELLED`、`TIMEOUT`。
- 仅在验签成功且金额、订单、计划快照一致时，才能进入核销成功路径。
- 金额不一致、授权取消、超时、重复通知、乱序回调都必须进入异常工单或死信，不得自动结清。

## 5. 文件与敏感资料交换

- 不通过普通 JSON 上传证件、视频、签名、合同或征信资料；使用短时、单次、域隔离的加密对象链接或端到端加密包。
- 对象访问需受限下载令牌、最短 TTL、用途审计与下载次数限制；URL 不入日志、错误响应或浏览器持久化。
- 接收后验证大小、MIME、恶意文件、内容 Hash 与归属订单；失败创建异常事件。

## 6. 错误、重试和观测

- `400` schema/字段错误；`401/403` 认证授权失败；`409` 幂等冲突或非法状态；`422` 业务前置未满足；`429` 限流；`5xx` 可重试系统错误。
- 指数退避、最大尝试数、死信队列和人工工单必须可配置；重试不得生成重复放款、重复钱包到账、重复提现、重复核销或重复结算。
- 日志只记录事件引用、域、状态码、Hash 前缀与追踪 ID；不得记录原始 PII、token、签名、证书或正文。

## 7. 接口验收

必须覆盖有效签名、坏签名、过期 timestamp、重复 nonce、重复 eventId、乱序回调、网络超时、短时文件链接过期、跨域资料越权、钱包到账幂等、提现回滚、银行授权还款成功/失败/取消/超时、金额 `number` 拒绝与审计追加写入。
