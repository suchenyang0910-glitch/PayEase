# V1 两域薪资贷接口与网络传输安全规范

**版本**：V1.0｜**状态**：开发基线｜**关联总则**：[规范基线](../00-导航与治理/V1_两域薪资贷_规范基线.md)

## 1. 传输与身份认证

- 仅 HTTPS/TLS 1.2+；生产跨域调用必须 mTLS，双方证书独立、90 天轮换、撤销可用。
- 每个请求签名 `Ed25519` 或经双方批准的等效方案；签名覆盖 method、path、body SHA-256、timestamp、nonce、keyId。
- 允许时钟偏差最多 300 秒；nonce 在接收域存储并防重放；密钥、证书、私钥只在对应域秘密管理服务中保存。
- API Gateway 仅开放明确 allowlist、速率限制、WAF 规则；管理接口永不直接公网暴露。

## 2. 统一消息信封

```json
{
  "eventId": "evt_...",
  "eventType": "LENDER_DECISION_AVAILABLE",
  "eventVersion": "v1",
  "sourceDomain": "LENDER",
  "occurredAt": "2026-08-21T00:00:00Z",
  "idempotencyKey": "...",
  "externalApplicationRef": "app_ext_...",
  "payload": {},
  "payloadSha256": "..."
}
```

接收方先校验 mTLS、签名、nonce、时间窗、schema 和幂等键，再写 Inbox 和 Outbox；业务处理异步、可重试。HTTP 成功只表示收到，不表示业务状态已经生效。

## 3. 允许的跨域事件

| 来源          | 事件                                                                                    | 最小化内容                                                         |
| ------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| KhmerX → 持牌 | `APPLICATION_PACKAGE_SUBMITTED`                                                         | 外部订单引用、经授权的申请加密包引用、合同/授权版本、请求证据 Hash |
| 持牌 → KhmerX | `LENDER_APPLICATION_RECEIVED`、`LENDER_MORE_INFO_REQUIRED`、`LENDER_DECISION_AVAILABLE` | 状态、可展示原因码、要约/合同安全引用；无征信原文                  |
| KhmerX → 持牌 | `CONTRACT_EVIDENCE_SUBMITTED`、`EMPLOYER_DEDUCTION_REPORTED`                            | 证据包 Hash、授权引用、执行状态/凭证引用                           |
| 持牌 → KhmerX | `DISBURSEMENT_CONFIRMED`、`COLLECTION_ACCEPTED`、`COLLECTION_EXCEPTION`                 | 实际放款时间、用户可展示账单投影、核销/异常状态                    |

融资居间服务费、工厂分润和 HR/财务运营信息均不进入持牌贷款账事件，除非双方 SOW 明确最小化字段与用途。

## 4. 文件与敏感资料交换

- 不通过普通 JSON 上传证件、视频、签名、合同或征信资料；使用短时、单次、域隔离的加密对象链接或端到端加密包。
- 对象访问需受限下载令牌、最短 TTL、用途审计与下载次数限制；URL 不入日志、错误响应或浏览器持久化。
- 接收后验证大小、MIME、恶意文件、内容 Hash 与归属订单；失败创建异常事件。

## 5. 错误、重试和观测

- `400` schema/字段错误；`401/403` 认证授权失败；`409` 幂等冲突或非法状态；`422` 业务前置未满足；`429` 限流；`5xx` 可重试系统错误。
- 指数退避、最大尝试数、死信队列和人工工单必须可配置；重试不得生成重复放款、重复核销或重复结算。
- 日志只记录事件引用、域、状态码、Hash 前缀与追踪 ID；不得记录原始 PII、token、签名、证书或正文。

## 6. 接口验收

必须覆盖有效签名、坏签名、过期 timestamp、重复 nonce、重复 eventId、乱序回调、网络超时、短时文件链接过期、跨域资料越权、金额 `number` 拒绝与审计追加写入。
