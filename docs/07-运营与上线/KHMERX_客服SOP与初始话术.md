# KhmerX 客服 SOP 与初始话术（试点版）

> **适用对象：** KhmerX 客服组长、客服专员、值班负责人。  
> **服务语言：** 高棉语优先；按用户选择提供英语或中文。  
> **业务边界：** PayEase 为 KhmerX 的个人金融产品。客服仅受理、说明、记录、催办和升级；不得决定或修改额度、利息、费用、合同、放款、还款核销或任何风控结论。

## 1. 服务目标与 SLA

| 场景                                 |  首次响应目标 |                更新频率 | 升级目标                 |
| ------------------------------------ | ------------: | ----------------------: | ------------------------ |
| 08:00–18:00 正常咨询                 |    0–1.5 小时 |              每个工作日 | 组长                     |
| 非服务时段普通咨询                   |      3–5 小时 |          下一个排班时段 | 组长                     |
| 登录、KYC、申请状态、还款页面异常    | 30 分钟内受理 | 每 4 小时或有进展即更新 | 值班负责人/技术值班      |
| 资金、合同、投诉、欺诈或个人信息事件 | 15 分钟内受理 | 每 2 小时或有进展即更新 | 组长 + 有权业务/合规角色 |

SLA 是响应与更新目标，不是审批、放款、退款、额度或问题解决的承诺。

## 2. 红线：必须做与绝不能做

### 必须做

1. 在受控工单中记录最少必要信息、分类、时间、当前事实、用户期望和升级去向。
2. 使用已批准的三语模板；不确定时先说明“正在核实”，再升级。
3. 对合同、放款、还款、投诉和安全事件转交有权队列，并保留转交时间和回执。
4. 发现疑似诈骗、错误收款账户、重复付款、账户被接管或资料泄露，立即停止引导用户继续操作并升级。

### 绝不能做

- 索取、接收或记录支付密码、OTP、银行卡完整号码、CVV、完整身份证/护照号、Telegram 登录验证码或私钥。
- 通过个人 Telegram、WhatsApp、私人邮箱、私人手机相册或群聊接收客户材料。
- 承诺“必批、秒到、保证额度、免审核、马上放款”，或猜测/披露内部风控规则。
- 代表用户签约、代替用户操作银行授权、修改用户资料、修改费用/额度/合同/核销结果。
- 将客户资料发给企业 HR、非本案人员或未授权合作方。

## 3. 标准流程

```text
接入 → 身份/事项最小核验 → 分类 → 受理与告知预计更新节点
→ 解答或创建工单 → 有权队列处理 → 客服更新用户 → 用户确认/超时关闭
→ 质检与复盘
```

### 3.1 接入与最小核验

1. 优先从 Mini App 内客服入口或指定 KhmerXBot 进入，自动关联受控用户/申请引用；没有引用时只做一般咨询。
2. 只确认显示昵称、工单号或申请引用的末尾若干位；不要请用户发送证件、完整手机号、银行卡或验证码。
3. 若用户疑似非本人、要求披露他人信息或使用非受控渠道：不提供账户/申请信息，转为一般安全提示。

### 3.2 分类与转办

| 分类                   | 客服可做                                     | 必须转办                                  |
| ---------------------- | -------------------------------------------- | ----------------------------------------- |
| 登录/Telegram/页面异常 | 收集非敏感错误描述、截图中打码、创建技术工单 | 技术值班                                  |
| KYC/补件/企业核验      | 说明所缺材料类型、提醒提交或等待             | 资料审核/企业协作队列                     |
| 额度/审批              | 说明“正在审核/结果已更新”等可见状态          | 有权审批队列；客服不可解释内部评分        |
| 合同/费用              | 说明可见合同版本、费用展示位置、投诉入口     | 合同/合规或有权业务队列                   |
| 钱包、提现、还款       | 引导至 SMILE 受控页面；记录回调异常          | 持牌资金/技术队列；客服不接收密码或卡信息 |
| 投诉                   | 受理、分类、保全事实、告知下一次更新节点     | 持牌机构投诉角色作最终结论                |
| 安全/欺诈              | 停止风险操作、给出安全提示、保留最少证据     | 安全事件负责人 + 合规                     |

### 3.3 工单字段与关闭

必填字段：`caseRef`、渠道、语言、分类、关联申请引用（如有）、事实摘要、当前用户可见状态、受理时间、责任队列、下次更新时间、处理结果代码。

关闭前必须确认：用户已获得明确答复或已被告知后续处理节点；投诉、资金和安全工单不得由客服自行以“已解决”关闭。

## 4. 质检与升级

1. 组长每周抽检至少 10% 工单，检查：身份边界、禁止索取项、准确性、语言、SLA、升级路径与记录完整性。
2. 发生误导承诺、敏感数据外发、未经授权查看、错误引导支付或遗漏资金/安全升级时，立即升级并保全审计记录。
3. 客服不能因担心绩效而延迟上报；正确升级风险事件属于合规表现。

## 7. 上线前验收

- [ ] KhmerXBot、Mini App 和后台工单分类与本 SOP 一致。
- [ ] 三语模板经过业务译者与合规复核；变量字段来自受控系统。
- [ ] 客服账号不能访问额度编辑、合同编辑、放款、核销或敏感原件下载。
- [ ] 模拟完成登录异常、KYC 补件、申请审核、钱包/还款异常、投诉、安全事件六类演练。
- [ ] 首期排班表、值班负责人、技术/合规/持牌投诉升级联系人已登记并演练。
