# 持牌机构投诉处理角色操作规范

## 目的

投诉的最终处理责任归持牌机构，但投诉处理不等同于授信、签约、放款或账务操作。本规范以最小权限原则将投诉工作限定给专属的 `LENDER_COMPLAINT_OFFICER` 角色。

## 授权边界

| 角色                                          | 可执行操作                                                 | 不可执行操作                                       |
| --------------------------------------------- | ---------------------------------------------------------- | -------------------------------------------------- |
| `BROKER_OFFICER`                              | 查看本平台受理的工单、补充处理记录、转交持牌机构           | 查看机构处理队列、作出最终结论、变更贷款或账务     |
| `LENDER_COMPLAINT_OFFICER`                    | 查看已转交工单、查看必要的申请与投诉内容、录入最终处理结论 | 授信、定价、签约、放款、还款核销、修改原始投诉内容 |
| `LENDER_CREDIT_OFFICER`、合同、放款及还款角色 | 无投诉队列、详情或结论权限                                 | 读取、处理或结案投诉                               |
| 企业端角色                                    | 无                                                         | 读取任何投诉信息                                   |

服务端对下列接口均强制检查 `LENDER_COMPLAINT_OFFICER`：

- `GET /v1/local/service-cases/referred-to-lender`
- `GET /v1/local/service-cases/:caseNo`（机构侧访问）
- `POST /v1/local/service-cases/:caseNo/lender-resolution`

前端隐藏不构成授权控制；没有该角色的会话仍会收到 `403 FORBIDDEN__ROLE_OUT_OF_SCOPE`。

## 账号与角色管理

平台管理员按“部门—角色—账号”维护持牌机构组织。为某位处理人员分配角色前，应确认其部门、雇佣关系和投诉处理授权；不应把该角色附加给授信、合同、放款或账务人员以图省事。角色撤销应在人员离岗、权限变更或安全事件时立即完成。

数据库迁移 `V0019__lender_complaint_officer_role.sql` 会幂等创建该角色；初始化流程也会在新环境中提供该角色定义，但不会自动把它授予任何真实账号。

## 审计与数据处理

投诉创建、详情访问、机构转交和最终结论均保留审计事件。投诉正文作为个人信息加密保存，日志中不得写入明文正文、证件号、电话号码或支付凭证。处理结论必须包含原因代码和面向用户的说明，并遵循柬埔寨当地法务确认后的保存期限、投诉话术和升级规则。

## 上线前核对

1. 至少指定一名、建议两名独立的持牌机构投诉处理专员。
2. 用非投诉机构角色验证队列、详情和结论接口均返回 403。
3. 用投诉处理专员角色完成“受理—转交—结论—用户可见”的演练。
4. 将投诉升级联系人、响应时限及法务批准版本写入运营手册后再开放真实用户流量。
