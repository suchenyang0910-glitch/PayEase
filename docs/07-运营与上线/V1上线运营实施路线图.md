# PayEase V1 上线运营实施路线图

> 估算基于“1 位工程负责人使用 Codex + Trae，另有产品/安全/合规/机构/企业负责人按需验收”的串行主路径。实际周期受 S0.2 签字、云账号与机构沙箱排期影响。

## 1. 总体里程碑

| 阶段 | 周期（签字完成后） | 目标                            | Exit Gate                                   |
| ---- | -----------------: | ------------------------------- | ------------------------------------------- |
| M0   |             0–2 周 | S0.2 签字、账号/区域/Owner 确认 | 五方签字与证据归档                          |
| M1   |             3–6 周 | S0.2/S0.3/S0.4 生产基础能力     | 三域 staging、IaC 扫描、日志告警、恢复演练  |
| M2   |            7–11 周 | S1 用户申请与授权               | Telegram 会话、申请、授权、文件与审计端到端 |
| M3   |           12–15 周 | S2/S3 企业核验与运营后台        | 租户/RBAC、批量核验、补件与双控             |
| M4   |           16–20 周 | S4 机构接入                     | 首家机构沙箱全链路、mTLS、回调故障演练      |
| M5   |           21–24 周 | S5 结算与贷后                   | 子账本、账单、对账与差异闭环                |
| M6   |           25–30 周 | S6 试点上线                     | 安全测试、渗透、UAT、灰度和运营值班         |

任何阶段的 P0 Gate 失败，后续阶段暂停；不得以 mock 通过替代真实环境验收。

## 3. 运营模型最小闭环

1. 企业准入：企业签约、管理员创建、字段与 SLA 确认。
2. 用户申请：Telegram 登录、授权、申请、文件与状态展示。
3. 企业核验：HR/FIN 只核验被授权字段；超时/争议进入工单。
4. 机构决策：机构独立完成 KYC/AML、授信、定价、合同和放款。
5. 助贷运营：只负责资料完整性、流程协调、通知与客服，不参与授信。
6. 结算/贷后：以持牌机构事实为准，对账差异冻结并由双控处理。
7. 风险控制：告警、值班、投诉、数据主体请求和事故响应闭环。

## 4. 首次受控试点成功标准

- 1 家机构、3–5 家企业、单币种、单一还款通道；用户严格白名单。
- 申请→授权→核验→机构结果→签约/放款状态→账单至少完成 10 条非生产测试链路和受控真实链路 UAT。
- 零 P0/P1 未关闭安全问题；所有 §4 上线红线有可核验记录。
- 对账差异、撤回授权、文件误访问、回调重放和密钥泄露均完成演练并关闭改进项。
