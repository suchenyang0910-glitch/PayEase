# PayEase V1 上线运营就绪度与缺口矩阵

> 版本：v1.0（规划基线）
> 适用目标：柬埔寨单国、1 家持牌机构、3–5 家企业、单一币种与单一还款通道的受控试点。
> 结论：当前仅可进行静态 Demo 与纯模拟演练；**不可接入真实用户、真实 PII、真实资金、真实机构或企业系统**。

## 1. 目标分层与准入结论

| 层级 | 目标                                            | 当前状态       | 准入结论       |
| ---- | ----------------------------------------------- | -------------- | -------------- |
| L0   | 静态 Demo：门户展示、mock 数据、离线文档        | 已具备基础能力 | 可用于内部演示 |
| L1   | 工程可开发：三域隔离环境、持续集成、可观测性    | 未完成         | 不可接真实数据 |
| L2   | 受控试点：白名单用户、真实机构沙箱/受控生产链路 | 未完成         | 不可启动       |
| L3   | 正式生产：可扩展真实用户运营                    | 未完成         | 不可启动       |

## 2. 已完成资产（不等同于生产能力）

| 范围         | 已有资产                                                      | 边界                                     |
| ------------ | ------------------------------------------------------------- | ---------------------------------------- |
| 工程基础     | pnpm workspace、共享 Money / Security 包、基础 GitHub Actions | 不含真实后端、数据库、部署流水线         |
| 静态安全门禁 | Semgrep、金额类型守卫、许可证守卫、Gitleaks 工作流            | 未覆盖 CodeQL、SBOM、镜像/IaC 扫描、DAST |
| 门户 Demo    | HR 与财务 Vite/React 静态门户、mock 数据、网络零调用测试      | 无真实认证、租户、API、数据持久化        |
| 契约与规则   | Zod stub、RBAC fixture 骨架、连接器 fixture 规范              | 不是正式版本化 API 契约                  |

### P1：受控试点前应完成

- 三语正式文案、产品披露、隐私与授权文本由法务/机构定版。
- 运营工作台：补件、双人复核、SLA、异常工单、审计检索。
- 客服/投诉流程、机构/企业 UAT、培训材料与值班表。
- 合作方 SLA、DPA、数据保留与删除证明流程。

### P2：不阻塞首个受控试点，但应进入后续计划

- 多机构路由、多还款通道、多币种与企业代扣。
- Web3/稳定币能力（默认 No-Go，见 `WEB3_SETTLEMENT_PRE_RESEARCH.md`）。
- 高级 BI、自动化风险策略实验、跨国部署。

## 5. 不可突破的边界

S0.2 未签字并归档前，禁止：

1. 编写 Terraform 或申请/配置任何真实云资源。
2. 接入真实 Telegram、SAML/OIDC/SCIM、HRIS、ERP、银行、支付或持牌机构接口。
3. 收集、导入、传输或存储真实个人数据、证件、账户、薪资或资金数据。
4. 让助贷域做授信、定价、合同或放款决策，或共享三域数据库/密钥。

## 6. 下一阶段唯一优先级

先完成 `SECURITY_S0_2_CHECKLIST.md` 的实体签字和归档，再开始 S0.2。签字前仅允许继续推进纯文档、fixture、测试与静态演练工作。
