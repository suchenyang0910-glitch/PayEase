# PayEase 用户小程序页面像素级测试用例

> 版本：v1.0
> 适用范围：`user-mini-app` 当前 V1 页面与详情页
> 目标：在上线前完成移动端页面的像素级验收，确保布局、间距、字号、颜色、图标、按钮、折行、暗色模式与三语文案在真实手机宽度下表现一致，且**不出现横向溢出、遮挡、错位、重复 CTA、不可点击区域过小**等问题。

## 1. 验收结论口径

页面像素级测试不是“看起来差不多”，而是以下条件必须同时满足：

1. 页面在 `320 / 360 / 375 / 390 / 414` 宽度下无横向滚动。
2. 主内容均在安全区内，左右留白符合当前设计基线。
3. 标题、副文案、长标签、三语文案、按钮文案允许自然折行，不得截断关键信息。
4. 主 CTA、次 CTA、返回入口、底部导航、通知入口、帮助入口都具备稳定点击区，无遮挡。
5. 浅色/深色模式下对比度可读，不能出现浅底浅字或暗底暗字。
6. 同一业务状态只出现一个正确 CTA，不允许重复操作入口。
7. 与冻结规格不一致的视觉偏差，按缺陷等级入库，不得口头忽略。

## 2. 测试矩阵

### 2.1 设备宽度

| 档位 | 宽度 | 用途                                                 |
| ---- | ---- | ---------------------------------------------------- |
| XS   | 320  | 极限窄屏，验证顶部品牌区、长副文案、步骤条、按钮换行 |
| S    | 360  | Android 常见宽度，作为主验收基线                     |
| M    | 375  | iPhone 常见宽度，验证标题与卡片层级                  |
| L    | 390  | 新款 iPhone 常见宽度，验证卡片比例与留白             |
| XL   | 414  | 大屏手机，验证组件不会被拉散                         |

### 2.2 主题

| 主题 | 必测页面                                          |
| ---- | ------------------------------------------------- |
| 浅色 | 全量页面                                          |
| 深色 | 首页、借款页、申请 1-5 步、账单页、通知页、我的页 |

### 2.3 语言

| 语言    | 重点风险                             |
| ------- | ------------------------------------ |
| `zh-CN` | 长中文标题、步骤名、帮助文案         |
| `en`    | 按钮文案长度、分页文案、帮助详情标题 |
| `km`    | 高棉语折行、行高、字重、按钮高度     |

### 2.4 运行环境

| 维度   | 要求                                      |
| ------ | ----------------------------------------- |
| 浏览器 | Chrome 移动端仿真 + Telegram WebView 实机 |
| DPR    | 2x 或 3x，截图基线固定                    |
| 状态栏 | 不遮挡顶部导航与品牌区                    |
| 数据   | 使用固定测试账号与稳定 mock/seed 数据     |

## 3. 前置数据

执行前准备以下稳定数据，避免因空数据导致截图基线漂移：

1. 1 条可见的测试工厂数据。
2. 1 条审核中申请。
3. 1 条可查看详情的借款记录。
4. 1 条有账单信息的数据。
5. 至少 3 条通知，覆盖未读、已读、深链目标不同的情况。
6. 帮助页 `借款指南` 与 `安全防骗` 使用正式文案版本。

## 4. 全局像素级检查项

每个页面都必须先过这一层，再看页面级用例。

| 检查项   | 验收标准                                                     |
| -------- | ------------------------------------------------------------ |
| 横向溢出 | `document.documentElement.scrollWidth === window.innerWidth` |
| 安全区   | 页面主内容不可顶边、贴边、压住底部导航                       |
| 标题层级 | 一级标题、二级标题、正文、辅助文案层级清晰                   |
| 按钮尺寸 | 主要按钮点击高度不小于 44px，文案垂直居中                    |
| 折行     | 长标题、长说明、三语文案不得超出容器边界                     |
| 图标     | 顶部铃铛、客服、底部导航图标描边清晰且居中                   |
| 颜色     | 使用统一 `--kx-*` 语义色，不出现旧绿色残留                   |
| 焦点态   | 可交互元素具备 hover/focus-visible 后的清晰状态              |
| 页面切换 | 进入详情页后，返回按钮、标题、卡片层级不跳动                 |

## 5. 截图与对比规则

1. 每个用例至少产出 1 张基线图；高风险页面需要浅色/深色各 1 张。
2. 文件命名建议：`<case-id>__<page>__<lang>__<theme>__<width>.png`
3. 像素差异阈值建议：
   - 关键页面：`<= 0.10%`
   - 一般页面：`<= 0.20%`
4. 允许差异仅限：
   - 时间、随机头像、通知时间戳等动态内容
   - 系统字体渲染的轻微抗锯齿差异
5. 不允许差异：
   - 间距变化
   - 文案折行变化
   - 按钮高度变化
   - 图标偏移
   - 卡片阴影/边框状态丢失
   - 暗色模式颜色失真

## 7. 高风险专项

以下问题即使只出现一次，也应按 P0/P1 处理：

| 风险              | 等级 | 说明                                              |
| ----------------- | ---- | ------------------------------------------------- |
| 页面横向溢出      | P0   | 任何主流程页面在手机宽度下出现横向滚动            |
| CTA 重复或错位    | P0   | 同一状态出现两个主 CTA，或主 CTA 被挤到屏幕外     |
| 步骤条遮挡 / 溢出 | P0   | 申请步骤在 320/360 下超出屏幕，导致无法理解或点击 |
| 暗色模式不可读    | P0   | 背景与文字对比不足，影响基本阅读                  |
| 三语文本裁切      | P1   | 中文/英文/高棉语出现半截裁切、压行或重叠          |
| 图标与文案未对齐  | P1   | 顶部导航、底部 Tab、通知标签错位明显              |
| 内页边距不一致    | P1   | 借款、账单、通知、我的之间左右留白基线不统一      |

## 8. 缺陷记录模板

每个视觉缺陷必须附以下字段：

- 用例 ID
- 页面路径 / 页面名
- 语言
- 主题
- 设备宽度
- 截图（问题图 + 基线图）
- 预期结果
- 实际结果
- 是否阻塞上线

示例：

```md
- 用例 ID：VIS-010
- 页面：申请流程 / 步骤条
- 语言：zh-CN
- 主题：light
- 宽度：320
- 预期：5 个步骤在屏幕内完整显示，长文案允许折行
- 实际：第 3 步“工厂与收款账户”撑出右边界，出现横向滚动
- 结论：P0，阻塞上线
```

## 9. 上线前最小通过标准

以下条件全部满足，页面像素级验收才算通过：

1. 第 6 节全部用例执行完成。
2. `VIS-001` 至 `VIS-024` 无 P0 缺陷遗留。
3. `320 / 360 / 375` 三档宽度的主流程截图全部留档。
4. 首页、申请 1-5 步、账单、通知、我的在浅色/深色模式均完成对比。
5. `zh-CN / en / km` 三语至少各完成 1 轮长文案折行检查。
6. 所有已知视觉缺陷都已关联截图和修复结论。

## 10. 建议执行顺序

建议按以下顺序执行，效率最高：

1. 全局壳层与导航
2. 首页与帮助详情
3. 借款页与申请 1-5 步
4. 借款记录 / 重新评估 / 借款详情
5. 账单页
6. 通知列表 / 详情
7. 我的页
8. 深色模式
9. 三语长文案
10. 320 窄屏专项回归

这份文档可直接作为人工验收清单，也可作为后续截图对比自动化的基线清单。
