# 数据库表结构（V1）

> 每个域拥有独立数据库。本文件描述逻辑表；生产环境需按数据库选型补充分区、索引、加密和迁移脚本。

## 1. 助贷平台数据库（broker_db）

| 表                          | 主键 | 关键字段                                                                                                                 |
| --------------------------- | ---- | ------------------------------------------------------------------------------------------------------------------------ |
| `users`                     | `id` | telegram_user_ref、locale、created_at                                                                                    |
| `applications`              | `id` | application_no、user_id、employer_id、lender_id、currency、requested_principal_minor、term_count、status、status_version |
| `application_status_events` | `id` | application_id、from_status、to_status、source、trace_id、occurred_at                                                    |
| `documents`                 | `id` | application_id、type、encrypted_object_key、content_hash、review_status、expires_at                                      |
| `bank_accounts`             | `id` | application_id、encrypted_pan、masked_pan、holder_verification_status                                                    |
| `consents`                  | `id` | application_id、purpose、field_scope_json、text_version、expires_at、revoked_at                                          |
| `employment_verifications`  | `id` | application_id、employer_id、status、result_json、verified_at                                                            |
| `review_cases`              | `id` | application_id、queue、status、assignee_id、reviewer_id、sla_due_at                                                      |
| `broker_fee_rules`          | `id` | fee_code、version、method、amount_or_rate、scope_json、approval_status、effective_at                                     |
| `broker_fee_snapshots`      | `id` | application_id、rule_id、amount_minor、currency、disclosure_version、user_confirmed_at                                   |
| `lender_offer_snapshots`    | `id` | application_id、lender_offer_id、payload_json、payload_hash、expires_at                                                  |
| `integration_events`        | `id` | partner、event_type、external_event_id、trace_id、payload_hash、received_at                                              |
| `audit_events`              | `id` | actor_type、actor_id、action、entity_type、entity_id、before_hash、after_hash、occurred_at                               |

建议索引：`applications(application_no)`、`applications(status, created_at)`、`consents(application_id, revoked_at)`、`integration_events(partner, external_event_id)` 唯一、`audit_events(entity_type, entity_id, occurred_at)`。

## 4. 关键约束

- 所有金额以 `BIGINT` 最小货币单位保存，并必须保存 `currency CHAR(3)`。
- PAN、证件号码、原始文件地址使用 KMS/信封加密；列表只读取脱敏列。
- 事件表追加写，不执行更新或删除；业务软删除必须记录原因和操作者。
- 机构、企业和助贷间只使用外部引用 ID，不使用对方数据库主键。
