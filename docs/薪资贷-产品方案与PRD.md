# 薪资贷产品方案与 PRD（V1）

## 1. 产品概述

**产品名称（暂定）**：薪易贷  
**用户入口**：Telegram Mini App，用户通过 Telegram 授权登录，无需手机号 OTP。  
**支持语言**：高棉语（km）、英语（en）、简体中文（zh-CN）；默认跟随 Telegram 语言，用户可手动切换。  
**支持币种（V1）**：默认美元（USD/$），可选柬埔寨瑞尔（KHR/៛）；每笔申请、报价、合同、账单和费用快照仅对应一种币种。  
**产品范围（V1）**：最低借款金额 USD 10（或等值 KHR），期限覆盖 10 天至 6 个月；实际额度和期限由持牌机构产品规则与审批结果决定。  
**目标用户**：已签约企业的在职受薪员工，优先覆盖工资稳定、可被企业授权核验的群体。  
**核心价值**：让员工在熟悉的 Telegram 内完成申请与进度查询；让企业以最小操作成本提供经授权的在职与薪资核验；让持牌机构获得结构化、可追溯的信贷资料。

### 角色与边界

| 角色          | 核心职责                                               | 不应承担的职责                         |
| ------------- | ------------------------------------------------------ | -------------------------------------- |
| 用户          | 授权、提交申请、签约、还款                             | 提供未经授权的企业数据                 |
| 助贷公司      | 获客、KYC 协助、资料收集、企业接入、状态通知、贷后提醒 | 最终授信、定价、放款、代替持牌机构签约 |
| 持牌机构      | 风控准入、授信定价、合同、放款、资金与贷后决策         | 将核心信贷决策外包给助贷方             |
| 企业财务/人事 | 管理企业接入、核验员工在职/薪资信息、处理异议          | 向未获员工授权的一方披露数据           |

## 2. V1 目标与非目标

### 目标

1. 建立「企业白名单 + 员工授权核验」的申请闭环。
2. 将申请、核验、授信、签约、放款状态统一回传给用户。
3. 让 HR/财务以列表审核与批量导入完成核验。
4. 为每次授权、数据读取、决策回传保留审计记录。

### 非目标

- 不做现金放款或平台自营资金池。
- 不接入无授权的通讯录、相册、聊天记录等高敏感数据。
- V1 不做企业代扣；还款通道由持牌机构或其合规支付合作方提供。
- V1 不自动拒绝用户：无法自动通过的申请进入持牌机构人工复核或给出可解释的补件路径。

## 3. 核心流程与状态

申请状态：`草稿 → 已提交 → 待企业核验 → 已核验 → 持牌机构审核 → 待签约 → 放款中 → 已放款 → 结清/逾期/关闭`

核验状态：`待核验 → 已通过 → 需补充 → 不匹配 → 已过期`

## 4. 功能需求

### 4.1 用户端（Telegram Mini App）

| 模块       | P0 能力                                                                        | 验收标准                                                                                  |
| ---------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------- |
| 登录与身份 | Telegram 授权登录、服务端会话校验、基础档案初始化                              | 拒绝不可信或过期的 `initData`；首次打开完成授权即可进入申请                               |
| 多语言     | 高棉语、英语、简体中文文案与格式化                                             | 默认读取 Telegram `language_code`；用户切换后持久化偏好；合同及合规文本以机构确认版本为准 |
| 产品展示   | 展示年化成本、期限、还款示例、合作持牌机构主体、预设及手动输入借款金额         | 手动金额按当前币种校验；成本、合同主体、隐私与授权入口在提交前可见                        |
| 申请       | 金额、期限、职业与收入信息、身份证正反面、身份证号码、本人银行卡信息、授权勾选 | 必填校验、草稿保存、授权版本留痕；实名/KYC 由持牌机构流程完成                             |
| 企业核验   | 选择所属企业，展示将共享的字段与用途                                           | 用户明确确认后才向企业发起核验                                                            |
| 审批与签约 | 状态时间线、补件、合同预览/签约跳转                                            | 每个状态有下一步及异常说明                                                                |
| 借款管理   | 还款计划、还款入口、还款记录、客服与投诉                                       | 金额和日期以持牌机构账务结果为准                                                          |

### 4.2 企业端（财务/人事 Web）

| 模块     | P0 能力                                | 验收标准                                     |
| -------- | -------------------------------------- | -------------------------------------------- |
| 企业管理 | 企业资料、管理员、权限分级             | HR 仅看员工核验；财务可看结算/报表（若启用） |
| 员工核验 | 待办列表、单笔确认、批量导入、异议退回 | 只展示已授权字段；每次操作可追溯             |
| 数据源   | CSV/XLSX 导入、模板校验、字段映射      | 导入错误逐行标明，不覆盖历史结果             |
| 通知     | 待核验提醒、过期提醒、核验结果回执     | 不在 Telegram 通知中暴露敏感信息             |

### 4.3 助贷运营端

企业准入、渠道管理、申请工单、资料质检、异常处理、客服工单、数据看板及审计检索。运营端只展示完成职责所需的最小字段；授信结论以持牌机构接口结果为准。

### 4.4 持牌机构接口

申请推送、资料补传、核验结果回传、授信结果、合同/签约链接、放款结果、账单/还款状态、风险事件与回调重试。所有请求须带幂等键、签名、时间戳和可追溯流水号。

## 5. 关键规则

1. Mini App 的访问仅依赖 Telegram 授权登录；不得以 Telegram 账号替代持牌机构要求的实名/KYC。
2. 企业核验须建立在用户单次、可撤回、可审计的授权上；授权过期后不可复用。
3. 身份证照片、证件号码和银行卡号属于高敏感资料：采集前须明确告知用途与接收方，前端展示和运营后台仅显示脱敏值，原件使用加密对象存储及短时授权访问。
4. 银行卡必须由用户本人持有；录入后应进行卡号格式、开户人一致性及必要的绑卡/验证校验，具体规则以持牌机构要求为准。
5. 只传递准入所需字段，例如在职状态、入职日期、薪资区间/近 N 月发薪结论；优先传核验结论而非完整工资单。
6. 助贷侧仅做资料完整性与反欺诈辅助规则；授信、额度和利率由持牌机构输出。
7. 申请撤回、授权撤回与数据删除请求须有受理入口；已为履行合同、反洗钱或法定义务保留的数据按适用规则处理。
8. 状态通知不得含身份证号、完整薪资、授信额度、还款账号等敏感内容。

## 6. 业务指标

| 指标         | 定义                    | V1 观察目标            |
| ------------ | ----------------------- | ---------------------- |
| 申请完成率   | 提交申请 / 进入申请页   | 识别表单流失           |
| 企业核验时效 | 核验完成时间 - 发起时间 | 识别企业端瓶颈         |
| 核验通过率   | 已通过 / 已完成核验     | 校准企业准入与用户引导 |
| 审批回传时效 | 收到机构结果 - 推送申请 | 保障用户体验           |
| 放款成功率   | 放款成功 / 签约成功     | 发现通道与资料问题     |

## 7. 埋点与审计

埋点：进入申请、每步完成、授权展示/同意/撤回、提交、核验发起/完成、补件、签约跳转、还款入口。  
审计：操作者、角色、时间、请求 ID、授权版本、字段范围、数据来源、前后值摘要、IP/设备指纹（在合法及已告知范围内）。

## 8. MVP 发布范围

先选定 1 家持牌机构、3–5 家企业、单一币种与单一还款通道。上线门槛：接口联调完成、风控/合规评审通过、异常与投诉 SOP 完成、数据删除与授权撤回流程演练通过。
